# التصميم المتجاوب

مسار الويب — ليس Flutter. الهدف: تخطيط واحد يعمل من 320px إلى 1920px بأقل عدد ممكن من نقاط الانكسار.

## الجوال أولاً

اكتب أنماط العرض الأضيق بلا استعلام، ثم أضف بـ `min-width`.

```css
.layout { display: grid; gap: 16px; }             /* الجوال */
@media (min-width: 768px) {                        /* ثم توسيع */
  .layout { grid-template-columns: 240px 1fr; }
}
```

نمط `min-width` يعني أن الأنماط تُضاف لا تُلغى، فلا تتراكم قواعد تعيد ضبط قواعد. البدء من سطح المكتب يجبرك على `max-width` تلغي ما كتبته، وتتضاعف الأخطاء.

الميزانية العملية: **3 نقاط انكسار كحد أقصى** لمعظم المواقع. كل نقطة إضافية تضاعف سطح الاختبار.

## نقاط الانكسار من المحتوى لا من الأجهزة

لا تسمِّ نقاطك "iPhone" أو "iPad". الأجهزة تتغيّر والمحتوى لا.

الطريقة: وسّع نافذة المتصفح تدريجياً وراقب متى **ينكسر التخطيط** — نص يفيض، بطاقة تصير أعرض من اللازم، سطر يتجاوز 75 حرفاً، أو تظهر مساحة فارغة بلا معنى. عند تلك النقطة بالضبط ضع نقطة انكسار.

نقاط شائعة معقولة كنقطة بداية: `640px`, `768px`, `1024px`, `1280px`. لكن `paragraph تجاوز 78 حرفاً عند 900px` سبب أفضل من "لأن 1024 قياسي".

استعلامات أخرى مفيدة أكثر من العرض أحياناً:

| الاستعلام | متى |
|---|---|
| `(hover: hover)` | تفعيل تأثيرات المرور فقط على أجهزة بمؤشر |
| `(pointer: coarse)` | تكبير مساحات اللمس إلى ≥ 44×44px |
| `(prefers-reduced-motion: reduce)` | تعطيل الحركات |
| `(prefers-color-scheme: dark)` | الوضع الداكن الافتراضي |
| `(orientation: landscape)` | تخطيط مختلف للجوال المستلقي |

## الشبكات المرنة — تخطيط بلا استعلامات

أفضل تخطيط متجاوب هو الذي لا يحتاج media query أصلاً.

```css
/* بطاقات تنزل تلقائياً */
.grid {
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(min(280px, 100%), 1fr));
  gap: clamp(12px, 2vw, 24px);
}

/* شريط جانبي ينهار تحت المحتوى عند الضيق */
.with-sidebar {
  display: flex;
  flex-wrap: wrap;
  gap: 24px;
}
.with-sidebar > .side { flex: 1 1 260px; }
.with-sidebar > .main { flex: 999 1 60%; }
```

- `auto-fit` يمدّد الأعمدة الموجودة لملء الصف؛ `auto-fill` يترك أعمدة فارغة. للبطاقات استعمل `auto-fit`.
- `min(280px, 100%)` إلزامية لمنع الفيضان عند 320px.
- الحاوية الرئيسية: `width: min(100% - 2rem, 1200px); margin-inline: auto;` — عرض أقصى مع هامش جانبي مضمون.

## الصور المتجاوبة

الصورة الواحدة بحجم 2000px تُرسل للجوال هي أكبر سبب لبطء المواقع في الشبكات الضعيفة.

```html
<!-- نفس الصورة بأحجام مختلفة: اترك الاختيار للمتصفح -->
<img
  src="hero-800.webp"
  srcset="hero-400.webp 400w, hero-800.webp 800w, hero-1600.webp 1600w"
  sizes="(min-width: 1024px) 800px, 100vw"
  width="1600" height="900"
  alt="واجهة لوحة التحكم" loading="lazy" decoding="async">
```

- `srcset` بوصف `w` + `sizes` = المتصفح يحسب حسب العرض الفعلي وكثافة الشاشة.
- `sizes` تصف **العرض المعروض** لا حجم الملف؛ خطؤها يبطل الفائدة كلها.
- `width`/`height` (النسبة تكفي) تمنع قفز التخطيط.
- `loading="lazy"` لكل صورة تحت الطية، و**لا** تضعها على صورة البطل — تؤخّر LCP.

قاعدة الفرق: `srcset` = نفس الصورة بأحجام مختلفة. `<picture>` مع `<source media>` أو `type` = **صورة أو قصّ مختلف** للجوال، أو صيغة بديلة (AVIF ثم WebP ثم JPEG).

## الطباعة السائلة

```css
:root { --step-0: clamp(1rem, 0.95rem + 0.25vw, 1.125rem); }
h1 { font-size: clamp(1.75rem, 1.2rem + 2.6vw, 3rem); }
p  { font-size: var(--step-0); line-height: 1.75; max-width: 68ch; }
```

- النص الأساسي لا ينزل تحت `16px` على الجوال — أقل من ذلك يسبب تكبيراً تلقائياً في iOS داخل الحقول.
- الفقرات العربية تحتاج `line-height` بين `1.7` و`1.9` (مقابل 1.5 للاتينية) بسبب التشكيل والنقاط.
- `text-wrap: balance` للعناوين و`text-wrap: pretty` للفقرات يمنعان الكلمة اليتيمة في آخر سطر.
- لا تستعمل `vw` وحدها لحجم الخط: تكبير المستخدم يتوقف عن العمل. لازم `rem` داخل `clamp`.
- النص العربي قد يكون أطول أو أقصر من الإنجليزي بـ 20–30%؛ اختبر التخطيط باللغتين لا بلغة واحدة.

## الجداول على الشاشات الصغيرة

ثلاث استراتيجيات، اختر حسب البيانات:

| الاستراتيجية | متى | التنفيذ |
|---|---|---|
| تمرير أفقي | أعمدة كثيرة متساوية الأهمية | غلاف `overflow-x: auto` + `min-width` على الجدول |
| تحويل لبطاقات | ≤ 5 حقول لكل صف | إخفاء `thead` وعرض كل صف ككتلة مع تسميات |
| إخفاء أعمدة ثانوية | عمود واحد أو اثنان مهمان | `display: none` تحت 768px + رابط "تفاصيل" |

الجدول الذي يفيض بلا غلاف (`overflow-x: auto` مع `min-width` على الجدول نفسه) يكسر عرض الصفحة كلها — أشهر عيب متجاوب. القاعدة العامة: **الصفحة لا تمرّر أفقياً أبداً؛ العنصر العريض يمرّر داخل نفسه**.

## الفيديو والوسائط المضمّنة

```css
.video { aspect-ratio: 16 / 9; width: 100%; }
.video iframe { width: 100%; height: 100%; border: 0; }
img, video, svg, iframe { max-width: 100%; height: auto; }
```

`aspect-ratio` ألغت حيلة الحشو بنسبة 56.25%. وقاعدة `max-width: 100%` العامة تمنع أغلب حالات الفيضان مسبقاً.

## dvh ومشكلة شريط المتصفح

على الجوال يظهر شريط عنوان المتصفح ويختفي مع التمرير، فيتغيّر الارتفاع الفعلي.

| الوحدة | المعنى |
|---|---|
| `vh` | الارتفاع الكبير (شريط مخفي) — يسبب قصّ المحتوى |
| `svh` | الأصغر (شريط ظاهر) — آمن لكن يترك فراغاً |
| `lvh` | الأكبر صراحة |
| `dvh` | الديناميكي — يتغيّر مع الشريط |

- قسم بملء الشاشة: `min-height: 100svh` (لا يُقص أبداً) أو `100dvh` (يتبع الشريط، لكنه يسبب إعادة تخطيط أثناء التمرير).
- استخدم `min-height` لا `height` دائماً، حتى لا يُقص المحتوى الأطول.
- لوحة المفاتيح الافتراضية على الجوال تغيّر الارتفاع أيضاً؛ لا تبنِ تخطيطاً حرجاً على ارتفاع النافذة.
- `100vw` تتجاهل عرض شريط التمرير على سطح المكتب وتسبب تمريراً أفقياً بمقدار ~15px؛ استخدم `100%` أو `100dvw`.

## الاختبار

اختبر عند ثلاثة عروض على الأقل، وهذه تغطي الواقع:

| العرض | يمثّل | ما تفحصه |
|---|---|---|
| **360px** | جوال أندرويد شائع | لا تمرير أفقي، أزرار ≥ 44px، نص ≥ 16px |
| **768px** | لوح / جوال مستلقٍ | التخطيط بين حالتين، لا فراغات ضخمة |
| **1440px** | سطح مكتب | العرض الأقصى للمحتوى، طول السطر ≤ 75 حرفاً |

أضف اختباراً عند **320px** إن كان جمهورك يشمل أجهزة قديمة، و**اختبر بتكبير خط المتصفح 200%** — كثير من التخطيطات تنكسر هناك رغم نجاحها في تصغير النافذة.

## متجاوب مقابل متكيّف

| متجاوب (responsive) | متكيّف (adaptive) |
|---|---|
| تخطيط واحد سائل يتغيّر باستمرار | عدة تخطيطات ثابتة تُختار عند عتبات |
| CSS فقط، ملف HTML واحد | قد يتضمن كشف الجهاز على الخادم |
| يعمل على أي عرض حتى غير المتوقع | يبدو مثالياً عند العروض المستهدفة فقط |
| الافتراضي الصحيح اليوم | يُستعمل عند اختلاف جوهري في المحتوى بين الجوال والمكتب |

خلط الاثنين مقبول: تخطيط سائل عموماً + قرار متكيّف واحد (قائمة جانبية تصير درجاً على الجوال).

## أخطاء شائعة

- تصميم على شاشة 1440px ثم "إصلاح" الجوال بـ `max-width` متراكمة.
- نقاط انكسار مسمّاة بأجهزة، وعددها 7.
- صورة واحدة بحجم واحد لكل الشاشات.
- `height: 100vh` لقسم البطل فيُقص على iOS.
- جدول أو كتلة كود بلا غلاف تمرير فتكسر عرض الصفحة.
- تصغير النص على الجوال بدل تقليل المحتوى.
- إخفاء محتوى مهم على الجوال بـ `display: none` بدل إعادة ترتيبه.

> التخطيط المتجاوب داخل Flutter مختلف تماماً؛ افتح flutter-ui-design.

## قائمة تحقق

- [ ] كل الاستعلامات `min-width` والأنماط الأساسية للجوال
- [ ] عدد نقاط الانكسار ≤ 3 ومبرّرة بالمحتوى لا بأجهزة
- [ ] لا تمرير أفقي للصفحة عند 320px و360px
- [ ] الشبكات تستعمل `minmax(min(Xpx, 100%), 1fr)`
- [ ] كل الصور لها `srcset`/`sizes` أو `<picture>` مع `width`/`height`
- [ ] `loading="lazy"` لصور ما تحت الطية فقط، لا لصورة البطل
- [ ] الطباعة بـ `clamp()` مع `rem`، والنص الأساسي ≥ 16px، وطول السطر ≤ 75ch
- [ ] فقرات العربية بـ `line-height` ≥ 1.7 واختُبرت باللغتين
- [ ] الجداول والأكواد داخل غلاف `overflow-x: auto`
- [ ] الوسائط بـ `aspect-ratio` وقاعدة `max-width: 100%` عامة
- [ ] `svh`/`dvh` بدل `vh` مع `min-height` لا `height`
- [ ] فُحص عند 360 و768 و1440، وبتكبير خط 200%
