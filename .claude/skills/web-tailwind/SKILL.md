# Tailwind CSS بانضباط

مسار الويب — ليس Flutter. Tailwind ليس بديلاً عن معرفة CSS: كل صنف هو خاصية CSS واحدة. من لا يعرف `flex-basis` لن ينقذه `basis-64`.

## متى يصلح ومتى لا

| يصلح | لا يصلح |
|---|---|
| مشروع تكتبه وحدك أو بفريق صغير | فريق يفرض CSS منفصلاً عن القالب |
| مكوّنات React/Vue حيث القالب والنمط في ملف واحد | HTML يُولَّد من CMS لا تتحكم بقوالبه |
| نظام تصميم بمقاييس ثابتة | تصميم فني بقيم فريدة لكل عنصر |
| سرعة تكرار عالية | مكتبة مكوّنات تُوزَّع كـ CSS مستقل |

لا تستعمله مع مكتبة مكوّنات جاهزة لها نظام أنماط خاص إلا إذا كانت غير منمّطة (headless).

## الإعداد والتخصيص من رموز التصميم

الخطأ الأول: استعمال اللوحة الافتراضية كما هي، فيصير المشروع بلا هوية. عرّف رموزك ثم استعملها **فقط**.

في الإصدارات الحديثة يتم التخصيص داخل CSS نفسه عبر `@theme`؛ وفي الإصدارات الأقدم عبر `tailwind.config.js` تحت `theme.extend`. أياً كان الأسلوب، القاعدة واحدة:

```css
@import "tailwindcss";

@theme {
  --color-brand-500: oklch(0.62 0.16 250);
  --color-brand-600: oklch(0.54 0.16 250);
  --font-sans: "IBM Plex Sans Arabic", system-ui, sans-serif;
  --radius-card: 12px;
}
```

- استعمل `extend` لا الاستبدال الكامل، وإلا فقدت السلّم الافتراضي كله.
- لا تضف درجة لون لأنك احتجتها مرة؛ اللوحة تبقى محدودة (5–7 درجات للعلامة + محايدات).
- المسافات: التزم بالسلّم (`1` = 4px). `p-[13px]` علامة على أن التصميم خارج النظام.
- القيم العشوائية `w-[723px]` مسموحة كاستثناء نادر، وليست أسلوب عمل.

## ترتيب الأصناف

قائمة الأصناف تصير غير مقروءة بسرعة. اتفق على ترتيب واحد وطبّقه آلياً بإضافة `prettier-plugin-tailwindcss` التي تعيد الترتيب بنفسها.

الترتيب المنطقي عند الكتابة يدوياً:

```
التخطيط (flex/grid/block) → الموضع → الأبعاد → المسافات →
الطباعة → الألوان والخلفيات → الحدود والظلال → التأثيرات → الحالات (hover/focus) → المتغيّرات المتجاوبة
```

إذا تجاوز العنصر ~12 صنفاً فهذه إشارة إلى أنه يستحق أن يصير مكوّناً.

## استخراج المكوّنات مقابل ‎@apply

| الوضع | الحل |
|---|---|
| النمط يتكرر مع نفس البنية | مكوّن React/Vue يستقبل `props` |
| النمط يتكرر مع بنى مختلفة | صنف واحد بـ `@apply` أو CSS عادي |
| تنويعات (حجم، لون، حالة) | `cva` أو `tailwind-variants` مع `clsx`/`tailwind-merge` |
| استعملته مرة واحدة | اتركه في القالب |

القاعدة: **المكوّن أولاً، `@apply` أخيراً.** الإفراط في `@apply` يعيدك إلى CSS تقليدي بأسماء مخترعة وتفقد ميزة Tailwind كلها. `@apply` مقبول لثلاث حالات: عناصر أساسية عامة (`body`, `a`)، أنماط لا تملك قالبها (محتوى من محرر نصوص)، وطبقة `base` صغيرة.

```jsx
// دمج آمن للأصناف: tailwind-merge يحل التعارض لصالح الأخير
<button className={twMerge("px-4 py-2 rounded-lg bg-brand-600", className)} />
```

بدون `tailwind-merge` سيتعارض `px-4` القادم من `props` مع `px-4` الداخلي بترتيب غير محدد.

## الوضع الداكن

`dark:` يعمل بأحد وضعين: حسب تفضيل النظام، أو حسب صنف/سمة على `<html>` (الأفضل، لأنه يسمح بمبدّل يدوي).

```html
<html class="dark">
<div class="bg-white text-slate-900 dark:bg-slate-900 dark:text-slate-100">
```

- لا تكتب `dark:` على كل عنصر. عرّف متغيرات CSS للأسطح والنصوص وبدّلها مرة واحدة على الجذر، ثم استعمل `bg-surface` في كل مكان.
- الوضع الداكن ليس عكس الألوان: خفّض التشبّع، ولا تستخدم أسوداً خالصاً (`#000`) بل `#0f1216` تقريباً، والظلال تُستبدل بحدود خفيفة.
- تجنّب وميض الوضع الخاطئ: اقرأ التفضيل وطبّق الصنف في سكربت صغير قبل رسم الصفحة.

## الاستجابة

نقاط الانكسار تعمل **من الأصغر إلى الأكبر** (mobile-first): الصنف بلا بادئة هو الجوال، و`md:` يعني "من 768px فما فوق".

| البادئة | من |
|---|---|
| (بلا) | 0 |
| `sm:` | 640px |
| `md:` | 768px |
| `lg:` | 1024px |
| `xl:` | 1280px |
| `2xl:` | 1536px |

الخطأ الشائع: كتابة `md:hidden` ظناً أنها "أخفِ على الجوال" — بل العكس. للإخفاء على الجوال فقط: `hidden md:block`.

الاستجابة على مستوى المكوّن: `@container` مع بادئة `@md:` بعد وضع `@container` على الغلاف — أدق من نقاط انكسار النافذة للمكوّنات القابلة لإعادة الاستخدام.

## الدعم المنطقي للعربية

هذا أهم بند في مشروع عربي. Tailwind يوفّر أصنافاً منطقية تتبع `dir`:

| فيزيائي (تجنّبه) | منطقي (استعمله) |
|---|---|
| `pl-4` / `pr-4` | `ps-4` / `pe-4` |
| `ml-2` / `mr-2` | `ms-2` / `me-2` |
| `text-left` / `text-right` | `text-start` / `text-end` |
| `border-l` / `border-r` | `border-s` / `border-e` |
| `left-0` / `right-0` | `start-0` / `end-0` |
| `rounded-l-lg` | `rounded-s-lg` |

- ضع `dir="rtl"` على `<html>` وستنقلب كل الأصناف المنطقية تلقائياً — بلا ملف CSS ثانٍ ولا إضافة.
- `flex-row` لا تحتاج `flex-row-reverse` في RTL: الاتجاه يُشتق من `dir`. استعمال `flex-row-reverse` يدوياً يكسر الصفحة عند التبديل للإنجليزية.
- المقاطع اللاتينية (أرقام هواتف، IBAN، أكواد) داخل نص عربي تحتاج `dir="ltr"` على العنصر نفسه.
- النص العربي يحتاج ارتفاع سطر أعلى: `leading-relaxed` (1.625) بدل `leading-normal` كأساس للفقرات.
- بادئة `rtl:` و`ltr:` موجودة للحالات النادرة التي لا تحلّها الخصائص المنطقية (اتجاه أيقونة سهم مثلاً).

## تنظيف الإنتاج

Tailwind يمسح ملفاتك ويولّد الأصناف المستعملة فقط. حجم CSS النهائي لموقع متوسط يجب أن يكون **أقل من 20KB** قبل الضغط.

- تأكد أن مسارات المحتوى تشمل كل امتدادات القوالب (`.tsx`, `.html`, `.mdx`) وأي حزمة داخلية تحتوي أصنافاً.
- لا تضع مسارات مثل `./node_modules/**` — سيبطئ البناء بشكل حاد.
- تحقق من الحجم بعد البناء؛ إن تجاوز 50KB فغالباً هناك `safelist` واسعة أو مسار خاطئ.

## الخطأ الأخطر: سلاسل الأصناف الديناميكية

الماسح يقرأ الملفات كنص، ولا ينفّذ الكود. أي صنف مبني بالتركيب لن يوجد في CSS النهائي.

```jsx
// خطأ — لن يُولَّد أي منها
<div className={`text-${color}-500 p-${size}`} />

// صحيح — أصناف كاملة مكتوبة حرفياً
const TONE = {
  danger:  "text-red-600 bg-red-50",
  success: "text-green-600 bg-green-50",
};
<div className={TONE[tone]} />
```

هذا يعمل في التطوير ويفشل في الإنتاج — أخطر أنواع الأعطال. إن اضطررت لأصناف ديناميكية حقيقية، أضفها إلى `safelist` صراحة، أو استخدم متغيّر CSS مع قيمة عشوائية: `style={{ "--tone": color }}` ثم `bg-[var(--tone)]`.

## أخطاء شائعة أخرى

- `@apply` لكل شيء حتى يصبح المشروع CSS تقليدياً بخطوة بناء زائدة.
- خلط `pl-4` مع `ps-4` في نفس المشروع فينكسر RTL جزئياً.
- تكرار نفس 15 صنفاً في 30 مكاناً بدل مكوّن.
- تجاهل `tailwind-merge` فتظهر تعارضات عشوائية عند تمرير `className`.
- استعمال `!important` (`!bg-red-500`) لحل تعارض سببه غياب `twMerge`.
- إضافة درجات لون خارج النظام حتى تفقد اللوحة معناها.

> قرارات اللوحة والمسافات نفسها: مهارات design-*. أساسيات CSS خلف الأصناف: web-css-modern.

## قائمة تحقق

- [ ] الرموز (ألوان، خطوط، أنصاف أقطار) معرّفة في الثيم لا مبعثرة كقيم عشوائية
- [ ] `prettier-plugin-tailwindcss` مفعّل ويرتّب الأصناف آلياً
- [ ] كل الاتجاهات بأصناف منطقية (`ps/pe/ms/me/start/end/text-start`)
- [ ] `dir="rtl"` على `<html>` ولا يوجد `flex-row-reverse` يدوي
- [ ] فقرات النص العربي بـ `leading-relaxed` أو أعلى
- [ ] لا توجد سلاسل أصناف مركّبة ديناميكياً؛ الخرائط تحتوي أصنافاً كاملة
- [ ] `tailwind-merge` مستعمل في كل مكوّن يستقبل `className`
- [ ] التنويعات عبر `cva`/`tailwind-variants` لا عبر شروط متشابكة
- [ ] الوضع الداكن بصنف على الجذر + متغيرات، لا `dark:` على كل عنصر
- [ ] `hidden md:block` مفهوم بشكل صحيح (البادئات صعوداً لا نزولاً)
- [ ] حجم CSS بعد البناء أقل من 20KB ومسارات المحتوى تشمل كل القوالب
