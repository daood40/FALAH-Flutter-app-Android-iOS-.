# معالجة النص العربي

مهارة **معالجة نص على الخادم**: تطبيع، فهرسة، بحث، وقياس. كل ما يلي يُنفَّذ في قاعدة البيانات أو الوسيط قبل أن يصل النص إلى نموذج أو فهرس.

> عرض النص وRTL والخطوط: مهارتا design-arabic-typography وflutter-arabic-rtl.

## لماذا التطبيع أولاً

نفس الكلمة تُكتب بأشكال صحيحة متعددة: `إسم`/`اسم`، `مصطفى`/`مصطفي`، `مكتبة`/`مكتبه`، `الســـلام` بالتطويل، `2024`/`٢٠٢٤`. بلا تطبيع موحّد يفشل البحث بصمت ويتشظّى الفهرس وتكذب المقارنة.

قاعدتان حاكمتان: **دالة تطبيع واحدة تُستعمل حرفياً في الفهرسة وفي الاستعلام** — اختلاف بايت واحد بينهما يعني استرجاعاً منهاراً بلا رسالة خطأ. و**احتفظ بالنص الأصلي** في عمود منفصل؛ المطبَّع للبحث والمقارنة فقط، والعرض من الأصل.

## دالة التطبيع

```ts
// aggressive=true  → للبحث والفهرسة اللفظية
// aggressive=false → للتضمين والتخزين النظيف
const TASHKEEL   = /[\u064B-\u065F\u0670\u06D6-\u06ED]/g;   // التشكيل والألف الخنجرية
const TATWEEL    = /\u0640/g;                                     // ـــ
const INVISIBLE  = /[\u200B-\u200F\u202A-\u202E\u2066-\u2069\uFEFF\u00AD]/g;
const AR_DIGITS  = /[\u0660-\u0669]/g;                       // ٠-٩ عربية-هندية
const EXT_DIGITS = /[\u06F0-\u06F9]/g;                       // ۰-۹ فارسية
const PUNCT: Record<string, string> = {
  "،": ",", "؛": ";", "؟": "?", "٪": "%", "…": "...",
  "“": '"', "”": '"', "‘": "'", "’": "'", "–": "-", "—": "-",
};

export function normalizeAr(input: string, opts: { aggressive?: boolean } = {}): string {
  if (!input) return "";
  let t = input.normalize("NFKC");   // يحوّل أشكال العرض FB50–FEFF واللام-ألف إلى الحروف الأساسية
  t = t.replace(INVISIBLE, "").replace(TASHKEEL, "").replace(TATWEEL, "");
  t = t.replace(AR_DIGITS,  (d) => String(d.charCodeAt(0) - 0x0660));
  t = t.replace(EXT_DIGITS, (d) => String(d.charCodeAt(0) - 0x06F0));
  t = t.replace(/[،؛؟٪…“”‘’–—]/g, (c) => PUNCT[c] ?? c);

  if (opts.aggressive) {
    t = t.replace(/[\u0622\u0623\u0625\u0671]/g, "ا");   // آ أ إ ٱ → ا
    t = t.replace(/\u0649/g, "ي");                              // ى → ي
    t = t.replace(/\u0629/g, "ه");                              // ة → ه
    t = t.replace(/\u0624/g, "و");                              // ؤ → و
    t = t.replace(/\u0626/g, "ي");                              // ئ → ي
    t = t.replace(/\u0621/g, "");                               // ء منفردة
    t = t.replace(/(.)\1{2,}/g, "$1$1");                    // مططططول → مططول
  }
  return t.replace(/\s+/g, " ").trim().toLowerCase();       // toLowerCase للأجزاء اللاتينية
}
```

ونظير SQL ليُستعمل في عمود مولَّد وفهرس — يجب أن يكون `IMMUTABLE`:

```sql
create or replace function ar_norm(t text) returns text
language sql immutable strict parallel safe as $$
  select lower(trim(regexp_replace(
    translate(
      regexp_replace(normalize(t, NFKC),
        '[\u064B-\u065F\u0670\u06D6-\u06ED\u0640\u200B-\u200F\u202A-\u202E\uFEFF\u0621]',
        '', 'g'),
      'آأإٱىةؤئ٠١٢٣٤٥٦٧٨٩',
      'اااايهوي0123456789'),
    '\s+', ' ', 'g')));
$$;

alter table products add column name_norm text
  generated always as (ar_norm(name)) stored;
create index products_name_trgm on products using gin (name_norm gin_trgm_ops);
create index products_name_fts  on products using gin (to_tsvector('simple', name_norm));
```

قرارات صريحة داخل الدالة:

| التحويل | البحث/الفهرسة | التضمين | العرض |
|---|---|---|---|
| إزالة التشكيل | نعم | نعم | لا |
| إزالة التطويل والمحارف غير المرئية والـNFKC | نعم | نعم | نعم |
| توحيد الهمزات على الألف | نعم | لا | لا |
| `ة` → `ه` و`ى` → `ي` | نعم | لا | لا |
| توحيد الأرقام إلى لاتينية | نعم | نعم | قرار منتج |

**التطبيع العنيف للبحث فقط.** لا تخزّنه كنص المنتج ولا ترسله للنموذج كمحتوى معروض: `ة → ه` يجعل "مكتبة" و"مكتبه" متطابقين وهو مطلوب في البحث، لكنه يفسد النص المقروء ويضلّل النموذج في التلخيص. وللتضمين استعمل `aggressive: false`: أزل التشكيل والتطويل والمحارف الخفية وطبّق NFKC ووحّد الأرقام، واترك الهمزات والتاء المربوطة — نماذج التضمين تتعامل معها، والمحو العنيف يمحو تمييزاً مفيداً.

**في ليبيا الأرقام اللاتينية هي السائدة**، فالتوحيد إليها هو الافتراضي الآمن للبحث والتخزين؛ عرض الأرقام العربية-الهندية قرار عرض لا يدخل قاعدة البيانات. والخطأ الأكثر شيوعاً هنا: الاعتماد على `unaccent` — قواعده لا تغطي التشكيل العربي إطلاقاً، فتحتاج دالتك أنت.

## لماذا التجذيع العربي صعب

- الجذر ثلاثي والكلمة تُبنى بأوزان: من `كتب` تأتي كتاب، مكتبة، كاتب، مكتوب، اكتتاب. التجذيع الجذري يجمعها كلها فيخلط "مكتبة" بـ"كاتب" — استدعاء عالٍ ودقة منهارة.
- السوابق واللواحق تلتصق: `وبالمكتبات` = و + ب + ال + مكتب + ات، والقطع الخاطئ يشوّه الكلمة (`بارد` ← `ارد`).
- الغموض بلا تشكيل: `علم` قد تكون عِلْم أو عَلَم أو عَلِمَ، ولا مجذّع يحسم هذا بلا سياق. والأدوات المتاحة (مجذّعات خفيفة وأدوات تحليل صرفي) متفاوتة الجودة وثقيلة، ومجذّع Postgres المدمج للعربية بدائي.

**القرار العملي**: لا تعتمد على التجذيع كأساس. الترتيب الصحيح: تطبيع عنيف (يحلّ أغلب اختلافات الإملاء) ← `pg_trgm` للمطابقة التقريبية (يتحمّل السوابق واللواحق جزئياً بلا تحليل صرفي) ← بحث دلالي بالتضمين (يحلّ المرادف والصيغة الصرفية معاً) ← تجذيع خفيف كتحسين اختياري بعد قياسه؛ إن لم يرفع `recall@k` في تقييمك فاحذفه.

## الفصحى واللهجات

| البعد | الفصحى | اللهجات |
|---|---|---|
| بيانات التدريب | وفيرة | شحيحة، والمغاربية والليبية أشحّها |
| إملاء ثابت | نعم | لا — نفس الكلمة بعدة رسوم |
| أداء النماذج | جيد في الكبيرة والصغيرة | مقبول للمشرقية في الكبيرة، ضعيف للمغاربية وللنماذج الصغيرة |
| نماذج التضمين | جيدة | استرجاع أضعف بوضوح |

الأثر عندك: **المستخدم يكتب باللهجة والمحتوى مكتوب بالفصحى**، فتفشل المطابقة اللفظية والدلالية معاً. العلاجات مرتّبة بالمردود:

1. **توسيع الاستعلام**: نموذج صغير يعيد صياغة السؤال بالفصحى، فتبحث بالاستعلامين معاً وتدمج النتائج.
2. **قاموس مرادفات لهجية يدوي** لمجالك: 50–200 مدخلاً (`شن/ماذا`, `باهي/جيد`, `توة/الآن`, `حوش/منزل`) يُطبَّق على الاستعلام قبل الجانب اللفظي. رخيص ومردوده عالٍ جداً في مجال محدود.
3. **أمثلة قليلة بلهجة حقيقية** في مطالبة التصنيف — أقوى من أي وصف نصي للهجة. ولا تطلب من النموذج أن **يكتب** بلهجة محلية دقيقة إلا بعد اختبار؛ المخرج غالباً بلهجة مشرقية عامة تبدو غريبة للقارئ الليبي، والأأمن فصحى بسيطة قريبة من الكلام اليومي.

## البحث والمطابقة التقريبية

```sql
create extension if not exists pg_trgm;
set pg_trgm.similarity_threshold = 0.3;               -- الافتراضي 0.3
select id, name, similarity(name_norm, ar_norm($1)) as sim
from products where name_norm % ar_norm($1)           -- يستعمل فهرس gin_trgm_ops
order by sim desc limit 20;
```

| الحاجة | الأداة |
|---|---|
| مطابقة مع خطأ إملائي أو حرف ناقص | `pg_trgm` + `similarity` |
| بحث بكلمات متعددة في نص طويل | `to_tsvector('simple', name_norm)` + `websearch_to_tsquery` |
| إكمال تلقائي من بداية الكلمة | `name_norm like $1 || '%'` بفهرس `text_pattern_ops` |
| مرادفات وإعادة صياغة | تضمين دلالي |

عتبة `similarity` عملية: 0.3 متساهلة، 0.45–0.5 متوازنة لأسماء المنتجات القصيرة، وفوق 0.6 صارمة. عايرها على أسماءك الحقيقية.

استعمل تشكيلة `'simple'` لا مجذّعاً عربياً: أنت طبّعت مسبقاً وتتحكم في النتيجة، والمجذّع المدمج يضيف سلوكاً غير متوقع يصعب تشخيصه. وكلمات الوقف العربية (`في`, `من`, `على`, `هذا`) لا تُحذف تلقائياً مع `'simple'` — احذفها بقائمة صريحة إن أضرّت بالترتيب.

## الترميز وتكلفة الرموز

النص العربي يستهلك في المرمِّزات الشائعة تقريباً **ضعفاً إلى ثلاثة أضعاف** رموز نص إنجليزي بنفس المعنى، لأن حروفه تُرمَّز بوحدات أصغر وببايتات متعددة. أثره في أربعة مواضع: التكلفة (مضاعفات مقابلها الإنجليزي)، نافذة السياق (تمتلئ أسرع — "50 ألف رمز" نص عربي أقصر مما تظن)، حجم القطعة في RAG (قطعة 500 رمز عربية = كلام أقل بكثير)، و`max_tokens` (سقف مضبوط على تجربة إنجليزية يقطع الرد العربي في منتصفه). **قِس العامل بنفسك** على عيّنة من نصوصك عبر عدّاد رموز المزوّد واستخرج متوسط الرموز لكل حرف، ثم استعمله في كل تقدير تكلفة وكل ضبط سقف. لا تقدّر بعدد الكلمات إطلاقاً. والتشكيل الكامل يرفع عدد الرموز بشكل ملموس بلا فائدة للنموذج — أزله قبل الإرسال إلا إن كان موضوع المهمة نفسه.

> الحساب الكامل للفاتورة: مهارة ai-cost-optimization.

## التلخيص والتصنيف بالعربية

- **حدّد الطول بالجُمَل لا بالكلمات**: `لخّص في 3 جمل` أدق من `في 50 كلمة`؛ تقدير النموذج لعدد الكلمات العربية ضعيف.
- **امنع "العربية المترجمة" صراحة**: `اكتب بعربية فصحى بسيطة، بجمل قصيرة، لا تراكيب مترجمة حرفياً عن الإنجليزية`. بلا هذا تحصل على نص سليم نحوياً ثقيل الأسلوب.
- **الأسماء والأرقام تُنقل حرفياً**: `انقل الأسماء والمبالغ والتواريخ كما وردت بلا إعادة صياغة` — النماذج تميل لتعريبها أو تحويرها في المخرج العربي. و**قيم التصنيف إنجليزية دائماً** حتى لو كان المدخل عربياً: `late_delivery` لا `تأخير_التوصيل`. القيمة العربية تختلف بالهمزة والتشكيل والمسافة فتكسر المطابقة، وتُترجَم في العميل عند العرض.
- **أمثلة عربية إلزامية**، ومنها مثال بلهجة ومثال بنص مختلط عربي-إنجليزي (كود، أسماء منتجات لاتينية، روابط) — وإلا حاول النموذج ترجمة الجزء اللاتيني.

## تحويل الكلام إلى نص

الحدود الحقيقية بلا تجميل:

| الحالة | التوقّع |
|---|---|
| فصحى واضحة، تسجيل نظيف | جيد إلى ممتاز — قابل للاستعمال المباشر |
| لهجات مشرقية وخليجية شائعة | متوسط — يحتاج مراجعة |
| اللهجة الليبية والمغاربية | ضعيف — الأقل تمثيلاً في بيانات التدريب |
| تبديل لغوي داخل الجملة، أو ضجيج وعدة متحدثين | ضعيف إلى منهار |
| أسماء أعلام وأرقام ومبالغ | غير موثوق — أكثر ما يخطئ فيه وأخطر ما يُعتمد عليه |

قواعد بناء:
- **لا تبنِ فعلاً حرجاً على تفريغ آلي بلا مراجعة** (طلب، مبلغ، عنوان). اعرض النص للمستخدم ليصحّحه قبل التنفيذ.
- مرّر تلميحاً بالمجال والمصطلحات المتوقعة (أسماء المنتجات، المدن) إن دعم المزوّد ذلك؛ يحسّن الأسماء الخاصة بوضوح.
- سجّل 16kHz مونو، وقسّم الطويل عند فترات الصمت لا عند حدود زمنية عمياء. والصوت أثقل بكثير من النص على شبكة ليبية: اضغطه قبل الرفع وضع سقف مدة 60–120 ثانية.
- بعد التفريغ مرّر النص على `normalizeAr` ثم على تصحيح خفيف بنموذج صغير: `صحّح أخطاء التفريغ فقط، لا تعِد الصياغة ولا تغيّر الأرقام والأسماء`.

## تقييم المخرج العربي

المقاييس الآلية الشائعة للترجمة والتلخيص ضعيفة الدلالة للعربية بسبب تعدد الصيغ الصحيحة. المسار العملي بثلاث طبقات:

1. **فحوص شكلية آلية** (مجانية وحتمية): نسبة المحارف العربية > 70%؟ لا محارف غير مرئية؟ كل الأرقام والأسماء الواردة في المدخل موجودة في المخرج؟ الطول ضمن الحد؟ لا نص إنجليزي مقحم؟
2. **حَكَم نموذجي بمعايير ثنائية**: `natural_arabic` (ليست ترجمة حرفية)، `preserves_facts` (الأرقام والأسماء سليمة)، `register_ok` (المستوى اللغوي مناسب للجمهور)، `format` (الطول والصيغة).
3. **مراجعة بشرية معايِرة**: 20–30 مخرجاً تقرأها أنت، ونسبة اتفاقك مع الحَكَم يجب أن تتجاوز 85% وإلا فالمعايير غامضة. ومعيار "الطبيعية" لا يُقاس آلياً بثقة: اقرأ المخرج بصوتك، وإن لم تقله لزبون بهذا التركيب فهو فاشل مهما قال الحَكَم.

> منهجية التقييم كاملة: مهارة ai-evaluation.

## قائمة تحقق

- [ ] دالة تطبيع واحدة تُستعمل حرفياً في الفهرسة والاستعلام
- [ ] النص الأصلي محفوظ في عمود منفصل عن المطبَّع
- [ ] التطبيع يشمل NFKC والتشكيل والتطويل والمحارف غير المرئية والأرقام
- [ ] التطبيع العنيف (همزات، `ة`، `ى`) للبحث فقط، وخفيف للتضمين، ولا شيء للعرض
- [ ] الأرقام موحّدة إلى اللاتينية في التخزين والبحث، و`ar_norm` معرّفة `IMMUTABLE` في عمود مولَّد مفهرس
- [ ] لا اعتماد على `unaccent` ولا على تجذيع كأساس؛ trgm + تضمين أولاً
- [ ] قاموس مرادفات لهجية للمجال + توسيع الاستعلام للفصحى، وعتبة `similarity` معايَرة على بياناتك
- [ ] عامل الرموز العربي مقيس فعلياً ومستعمل في التكلفة و`max_tokens` وحجم القطعة
- [ ] التشكيل مُزال قبل الإرسال للنموذج ما لم يكن موضوع المهمة
- [ ] الطول محدّد بالجُمَل، ومنع صريح للعربية المترجمة، ونقل حرفي للأسماء والأرقام
- [ ] قيم التصنيف إنجليزية دائماً، والأمثلة عربية وتشمل لهجة ونصاً مختلطاً
- [ ] لا فعل حرج مبني على تفريغ صوتي بلا مراجعة المستخدم
- [ ] فحوص شكلية آلية + حَكَم بمعايير ثنائية معايَر مقابل 20–30 حكماً بشرياً
