# اختبار سلوك التطبيق مع الشبكة

القاعدة الحاكمة: **التطبيق الذي لم يُختبر على شبكة سيّئة لم يُختبر أصلاً.** الاختبار على WiFi سريع يغطّي حالة واحدة من إحدى عشرة — وهي الحالة التي لا يعيشها أغلب مستخدميك.

هذه المهارة عن **ماذا تختبر وما السلوك الصحيح**، لا عن كتابة طبقة الشبكة.

> تنفيذ طبقة الشبكة: افتح مهارة flutter-networking-api.

## مصفوفة الحالات الإجبارية

كل حالة تُختبر على **كل شاشة تجلب بيانات** وعلى **كل عملية كتابة**.

| # | الحالة | السلوك الصحيح | فشل صريح |
|---|---|---|---|
| 1 | إنترنت سريع | نتيجة طبيعية | — |
| 2 | بطيء جداً (2G، 50kbps) | مؤشّر تحميل يظهر خلال 200ms، والشاشة لا تتجمّد | لا مؤشّر، أو تجمّد الواجهة |
| 3 | متقطّع (يقطع ويعود كل 5 ثوانٍ) | إعادة محاولة تلقائية، لا انهيار، لا تكرار للطلب الناجح | صف مكرّر أو انهيار |
| 4 | بلا اتصال أصلاً | رسالة عربية واضحة + زر "إعادة المحاولة" + بيانات مخزّنة إن وُجدت | شاشة بيضاء أو "Exception" |
| 5 | انقطاع **أثناء** الطلب | لا فقدان لمدخلات المستخدم، ولا حالة نصف مكتملة | النموذج يُمسح، أو طلب نصف مسجَّل |
| 6 | مهلة (لا استجابة 60 ثانية) | قطع عند حد معروف (15–30s) ورسالة، لا انتظار لانهائي | دوران دائم |
| 7 | خطأ 500 | رسالة عربية عامة + إعادة محاولة، لا تفاصيل خادم | عرض نص الخطأ الخام |
| 8 | 401 أثناء الاستخدام (انتهاء الجلسة) | تحديث صامت للرمز، أو نقل لشاشة الدخول مع حفظ الوجهة | حلقة إعادة توجيه، أو فقدان ما كتبه المستخدم |
| 9 | 429 تحديد معدّل | احترام `Retry-After` وانتظار متدرّج | إعادة محاولة فورية متكرّرة |
| 10 | استجابة مشوّهة (HTML مكان JSON، حقل ناقص) | خطأ مُعالَج ورسالة، لا انهيار | crash عند parsing |
| 11 | استجابة بطيئة جداً (تصل بعد 30s) | إن كان المستخدم غادر الشاشة فالنتيجة تُهمَل | تحديث شاشة غير موجودة أو استثناء |

الحكم ثنائي لكل خلية: السلوك الصحيح تحقّق أم لا. لا يوجد "تقريباً".

## كيف تحاكي كل حالة

على جهاز أندرويد حقيقي (وهذا هو المرجع):

```bash
# قطع الإنترنت كاملاً مع بقاء الجهاز موصولاً بـ adb
adb shell svc wifi disable && adb shell svc data disable
adb shell svc wifi enable  && adb shell svc data enable

# وضع الطيران
adb shell cmd connectivity airplane-mode enable
adb shell cmd connectivity airplane-mode disable
```

- **بطيء جداً**: خيارات المطوّر لا تخنق الشبكة على أندرويد؛ استعمل شبكة الجوال في منطقة ضعيفة، أو نقطة اتصال من هاتف ثانٍ مع تقييد، أو اجعل الخادم نفسه يؤخّر الاستجابة (نقطة `/__slow` في بيئة الاختبار تنام 20 ثانية).
- **متقطّع**: بدّل `svc data` تشغيلاً وإطفاءً في حلقة كل 5 ثوانٍ أثناء استخدام التطبيق.
- **انقطاع أثناء الطلب**: اضغط زر الحفظ ثم أطفئ البيانات خلال ثانية. هذا أهم اختبار في القائمة كلها.
- **أخطاء الخادم**: أسهل طريقة نقاط اختبار في بيئة staging تُعيد 500 و401 و429 و`Retry-After` عند الطلب، ومسار يعيد HTML مكان JSON.
- **المحاكي**: يقبل تحديد سرعة وتأخير عند الإقلاع (خيارات `-netdelay` و`-netspeed`)، وهذا مفيد للفرز السريع فقط. **الحكم النهائي من جهاز حقيقي** لأن سلوك انتقال الشبكة الفعلي (WiFi → بيانات، فقدان الإشارة، إعادة الاتصال) لا يحاكيه المحاكي.

اختبار إضافي مهم في الواقع الليبي: **التبديل من WiFi إلى بيانات الجوال أثناء طلب جارٍ**. عنوان IP يتغيّر والاتصال ينقطع؛ التطبيق يجب أن يعيد المحاولة لا أن يعلّق.

## السلوك الصحيح — تفصيل قابل للفحص

**الرسائل**: كل حالة فشل تعرض نصاً عربياً يقول ما حدث وما العمل. معيار الفشل: ظهور أي من `SocketException`, `TimeoutException`, `FormatException`, `null`, `Error 500` على شاشة المستخدم.

| الحالة | نص مقبول |
|---|---|
| بلا اتصال | لا يوجد اتصال بالإنترنت. تحقّق من الشبكة ثم أعد المحاولة. |
| مهلة | استغرق الأمر وقتاً أطول من المتوقع. أعد المحاولة. |
| 500 | حدث خطأ لدينا. جرّب بعد قليل. |
| 401 | انتهت الجلسة. سجّل الدخول من جديد. |

**إعادة المحاولة**: تُختبر بثلاثة أسئلة — كم مرة (3 محاولات كحدّ)، وبأي تباعد (تصاعدي: 1s، 2s، 4s، لا فوري متكرر)، وعلى أي أخطاء (نعم لأخطاء الشبكة و5xx و429؛ **لا** لـ 400 و401 و403 و422 لأن إعادتها بلا فائدة). إعادة محاولة على 400 = فشل تصميم.

**حفظ مدخلات المستخدم**: اكتب نصاً طويلاً في نموذج، اقطع الشبكة، اضغط حفظ. المتوقع: النص باقٍ في الحقول والخطأ فوقه. فقدان النص فشل حرج — وهو أكثر سلوك يدفع المستخدم لحذف التطبيق.

**زر واحد لا زران**: عند الفشل يظهر مسار واحد واضح لإعادة المحاولة. لا رسالة تختفي تلقائياً بلا فعل ممكن.

## العمل بلا اتصال والمزامنة

يُختبر بتسلسل محدّد:

1. افتح التطبيق متصلاً وحمّل بيانات → أغلقه.
2. اقطع الاتصال تماماً وافتحه → **المتوقع**: البيانات المحمّلة سابقاً تظهر، مع مؤشّر أنها غير محدّثة. شاشة فارغة هنا فشل.
3. نفّذ ثلاث عمليات كتابة بلا اتصال (إضافة، تعديل، حذف) → المتوقع: تظهر فوراً في الواجهة مع علامة "بانتظار المزامنة".
4. أعد الاتصال → المتوقع: مزامنة تلقائية خلال ثوانٍ، وترتيب العمليات محفوظ، والعلامة تختفي.
5. تحقّق في القاعدة: **ثلاث عمليات = ثلاثة تغييرات، لا ستة.**

اختبارات التكرار الإجبارية:
- كرّر الخطوة 4 بقطع الاتصال في منتصف المزامنة → عند العودة لا تتكرر العناصر التي مرّت.
- أغلق التطبيق قسراً أثناء وجود عمليات معلّقة، ثم افتحه → العمليات ما زالت معلّقة وتُزامَن.
- عدّل نفس الصف من جهازين، أحدهما بلا اتصال → قاعدة حلّ التعارض معلنة ومختبَرة (الأحدث يفوز عادة)، والنتيجة ليست فقدان صامت للتعديل.

معيار النجاح النهائي للمزامنة: **عدد الصفوف في القاعدة = عدد العمليات التي نفّذها المستخدم، بلا زيادة ولا نقصان.** كل شيء آخر تفصيل.

## الطلبات المتزامنة والضغط المزدوج

| الاختبار | كيف | معيار النجاح |
|---|---|---|
| ضغط مزدوج على "حفظ" | نقرتان سريعتان على شبكة بطيئة | صف واحد فقط في القاعدة |
| ضغط متكرر على "دفع" | 5 نقرات متتالية | عملية دفع واحدة |
| خروج من الشاشة أثناء تحميل | ارجع قبل وصول الاستجابة | لا استثناء، لا تحديث لواجهة مُزالة |
| تمرير سريع في قائمة تحمّل صفحات | تمرير متواصل | لا تكرار عناصر، لا طلبات متراكمة بلا إلغاء |
| فتح نفس الشاشة مرتين بسرعة | تنقّل مزدوج | طلب واحد أو نتيجة متّسقة |
| بحث أثناء الكتابة | اكتب 10 أحرف بسرعة | الطلبات القديمة مُلغاة، والنتيجة تطابق آخر نص |

آخر بندين يكشفان العطل المسمّى "استجابة متأخرة تسبق حديثة": نتيجة بحث قديمة تصل بعد الجديدة وتستبدلها. معيار الفشل: النص في الحقل لا يطابق النتائج المعروضة.

## سيناريو الاختبار القصير قبل كل إصدار

على جهاز حقيقي، 15 دقيقة، وهو الحد الأدنى غير القابل للتفاوض:

1. افتح التطبيق في وضع الطيران → رسالة عربية + بيانات مخزّنة.
2. شغّل البيانات → تحميل تلقائي بلا تدخّل.
3. املأ أطول نموذج، اقطع الشبكة، احفظ → النص باقٍ ورسالة واضحة.
4. أعد الشبكة، احفظ → صف واحد في القاعدة.
5. أبطئ الشبكة، اضغط "دفع" مرتين → عملية واحدة.
6. أبطل الجلسة من لوحة التحكم واستعمل التطبيق → نقل لشاشة الدخول بلا فقدان بيانات.
7. بدّل WiFi ↔ بيانات أثناء تحميل → استمرار أو إعادة محاولة، لا تعليق.

أي بند يفشل = FAIL يمنع الإصدار.

```
تقرير اختبار الشبكة — 1.4.0 — Redmi 9A — 2026-09-09
النتيجة: FAIL | 11 حالة × 6 شاشات = 66 خلية | نجح 61، فشل 5

| الحالة | النتيجة | الملاحظة |
|---|---|---|
| بلا اتصال | PASS | رسالة عربية وبيانات مخزّنة على كل الشاشات |
| بطيء جداً | PASS | المؤشّر يظهر خلال 150ms |
| متقطّع | FAIL | شاشة الطلبات: صفّان مكرّران بعد 3 انقطاعات |
| انقطاع أثناء الطلب | FAIL | نموذج العنوان يُمسح كاملاً — حرج |
| مهلة | PASS | قطع عند 20s |
| 500 | PASS | — |
| 401 أثناء الاستخدام | FAIL | حلقة إعادة توجيه لشاشة الدخول |
| 429 | FAIL | إعادة محاولة فورية، Retry-After متجاهَل |
| استجابة مشوّهة | PASS | — |
| استجابة بطيئة بعد المغادرة | FAIL | استثناء عند الرجوع |
| المزامنة بعد العودة | PASS | 3 عمليات = 3 صفوف |

الحكم: FAIL — فقدان مدخلات المستخدم وحلقة 401 مانعان للإصدار.
```

## قائمة تحقق

- [ ] الحالات الإحدى عشرة مُختبَرة على كل شاشة تجلب بيانات
- [ ] الاختبار على جهاز حقيقي، والمحاكي للفرز السريع فقط
- [ ] التبديل بين WiFi وبيانات الجوال أثناء طلب جارٍ مُختبَر
- [ ] لا نص استثناء إنجليزي يظهر للمستخدم في أي حالة
- [ ] كل رسالة فشل عربية وتقول ما العمل، ومعها مسار إعادة محاولة
- [ ] المهلة محدّدة (15–30s) ومُختبَرة، لا انتظار لانهائي
- [ ] إعادة المحاولة تصاعدية، 3 محاولات كحد، وعلى أخطاء الشبكة و5xx و429 فقط
- [ ] لا إعادة محاولة على 400/401/403/422
- [ ] `Retry-After` محترم عند 429
- [ ] مدخلات المستخدم لا تُفقد عند فشل الحفظ
- [ ] 401 أثناء الاستخدام: تحديث صامت أو نقل للدخول بلا حلقة وبلا فقدان بيانات
- [ ] بلا اتصال: بيانات مخزّنة تظهر لا شاشة فارغة
- [ ] عمليات الكتابة بلا اتصال تظهر فوراً بعلامة انتظار
- [ ] المزامنة تلقائية عند العودة، ومقاطعتها لا تُنتج تكراراً
- [ ] عدد الصفوف في القاعدة = عدد عمليات المستخدم بالضبط
- [ ] قاعدة حلّ التعارض معلنة ومختبَرة من جهازين
- [ ] الضغط المزدوج على الحفظ والدفع يُنتج عملية واحدة
- [ ] طلبات البحث القديمة مُلغاة والنتيجة تطابق آخر نص
- [ ] الخروج من شاشة أثناء تحميل لا يسبّب استثناء
- [ ] سيناريو الـ15 دقيقة منفَّذ قبل كل إصدار ونتيجته مسجَّلة
