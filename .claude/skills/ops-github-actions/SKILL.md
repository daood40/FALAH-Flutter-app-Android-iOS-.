# GitHub Actions: جهاز البناء الوحيد

بلا حاسوب، الـ runner هو بيئة التطوير الفعلية. كل ما هنا يُدار من تطبيق GitHub أو من محرّر الملفات في الويب.

## بنية الملف

مكانه `.github/workflows/<name>.yml`. الاسم حرّ، لكن اجعله وصفياً (`ci.yml`, `deploy.yml`) لأنه يظهر في تبويب Actions.

```yaml
name: CI
on:
  push: { branches: [main] }
  pull_request:
  workflow_dispatch:
permissions:
  contents: read
concurrency:
  group: ci-${{ github.ref }}
  cancel-in-progress: true
jobs:
  test:
    runs-on: ubuntu-latest
    timeout-minutes: 15
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: '22', cache: 'npm' }
      - run: npm ci
      - run: npm test
```

`concurrency` مع `cancel-in-progress` إلزامي عملياً: بدونه كل دفعة تبدأ تشغيلاً جديداً وتبقى القديمة تحرق دقائق. و`timeout-minutes` على كل وظيفة يمنع وظيفة معلّقة من استهلاك 6 ساعات (السقف الافتراضي) قبل أن تُقتل.

## المحفّزات

| المحفّز | متى | فائدته من الجوال |
|---|---|---|
| `push` | دفعة إلى فرع محدّد | البناء بعد الدمج في `main` |
| `pull_request` | فتح/تحديث PR | البوابة التي تمنع دمج كود مكسور |
| `workflow_dispatch` | زر يدوي في تبويب Actions | **الأهم لك** — تشغيل بناء أو نشر بضغطة |
| `schedule` | cron بتوقيت UTC | فحوص ليلية، فحص تبعيات، نسخ احتياطي |
| `release` | نشر إصدار | رفع مخرجات الإصدار |
| `workflow_run` | انتهاء سير عمل آخر | ربط النشر بنجاح CI |

`workflow_dispatch` يقبل مدخلات تظهر كنموذج قبل التشغيل — وهذا ما يحوّل الجوال إلى لوحة تحكّم:

```yaml
on:
  workflow_dispatch:
    inputs:
      environment:
        type: choice
        options: [staging, production]
        default: staging
      dry_run: { type: boolean, default: true }
```

ثم `${{ inputs.environment }}` داخل الخطوات. **الشرط**: ملف فيه `workflow_dispatch` لا يظهر زره حتى يوجد الملف على الفرع الافتراضي — سبب "لماذا لا أرى الزر؟" في 90% من الحالات.

`schedule` بتوقيت UTC دائماً (ليبيا UTC+2 بلا توقيت صيفي، فاطرح ساعتين). والمهام المجدولة تُؤخَّر عند ذروة الحمل على GitHub وقد تتخطّى، ويوقفها GitHub تلقائياً بعد 60 يوماً من الخمول على المستودع.

## الوظائف والخطوات والمصفوفات

الوظائف تعمل **بالتوازي افتراضياً** وكل واحدة على runner نظيف بلا ملفات من غيرها. الخطوات داخل الوظيفة متسلسلة وتتشارك القرص.

```yaml
  build:
    strategy:
      fail-fast: false
      matrix: { node: ['20', '22'] }
    runs-on: ubuntu-latest
```

المصفوفة تولّد وظيفة لكل تركيبة. `fail-fast: false` يمنع إلغاء بقية التركيبات عند فشل واحدة — تريد رؤية كل النتائج لا أول فشل. احذر التمدّد: مصفوفة من 3 نسخ × 3 أنظمة = 9 وظائف تضرب استهلاكك تسعة.

ثبّت الإجراءات على وسم رئيسي (`actions/checkout@v4`) لا على `@main`. للإجراءات من طرف ثالث ثبّت على SHA كامل — الوسم قابل لإعادة التوجيه إلى كود جديد بلا علمك.

## التخزين المؤقت

أكبر مكسب زمني منفرد. أغلب إجراءات `setup-*` تحمل تخزيناً مؤقتاً مدمجاً (`cache: 'npm'`, `cache: 'pip'`) — استعمله قبل أن تكتب `actions/cache` يدوياً، ولا تخزّن فيه مخرجات البناء (مكانها artifacts).

```yaml
- uses: actions/cache@v4
  with:
    path: ~/.cache/<tool>
    key: ${{ runner.os }}-deps-${{ hashFiles('**/lockfile') }}
    restore-keys: |
      ${{ runner.os }}-deps-
```

`key` يجب أن يحوي بصمة ملف القفل — وإلا سيُخدَم لك تخزين قديم بتبعيات خاطئة. و`restore-keys` يقبل مطابقة جزئية فتستفيد جزئياً عند تغيّر تبعية واحدة. الحدود: 10 GB لكل مستودع (يُطرد الأقدم استعمالاً)، ويُحذف المدخل بعد 7 أيام بلا استعمال، والمشاركة محصورة بالفرع نفسه والفرع الافتراضي. الأثر النموذجي: تثبيت تبعيات من 3–4 دقائق إلى 20–40 ثانية.

## المخرجات (artifacts) والتحميل من الهاتف

```yaml
- uses: actions/upload-artifact@v4
  with: { name: web-build, path: dist/, retention-days: 7, if-no-files-found: error }
```

`if-no-files-found: error` مهم: بدونه، مسار خاطئ يُنتج artifact فارغاً ووظيفة خضراء كاذبة. و`retention-days` قصيرة توفّر من حصّة التخزين (الافتراضي 90 يوماً).

للتحميل من الجوال: تبويب Actions ← التشغيل ← أسفل صفحة الملخّص قسم Artifacts. الملف يُنزَّل **مضغوطاً zip دائماً** حتى لو رفعت ملفاً واحداً — طبيعي، افتحه بمدير ملفات. الرابط يتطلّب تسجيل دخول فلا يعمل بمشاركته مع غيرك؛ للمشاركة العامة استعمل GitHub Release بدل artifact.

`upload-artifact@v4` لا يسمح برفع باسم موجود في نفس التشغيل — في المصفوفة أضف لاحقة: `name: build-${{ matrix.node }}`. ولتمرير ملفات بين وظيفتين: `upload` في الأولى و`download-artifact@v4` في الثانية؛ ولتمرير قيم نصية استعمل `outputs` لا artifact.

## الأسرار والمتغيّرات والبيئات

| النوع | الموضع | يظهر في السجلّ؟ |
|---|---|---|
| Secret | Settings ← Secrets and variables ← Actions | لا، يُقنَّع تلقائياً |
| Variable | نفس الصفحة، تبويب Variables | نعم |
| Environment secret | Settings ← Environments ← البيئة | لا، ومقيّد بالبيئة |

القراءة: `${{ secrets.SUPABASE_SERVICE_ROLE }}` و`${{ vars.API_BASE_URL }}`. السرّ يُكتب مرة ولا يُقرأ ثانية — لا واجهة تعرضه، فاحتفظ بنسخة في مدير كلمات مرور.

البيئات تضيف طبقتين: **required reviewers** توقف التشغيل حتى توافق من الجوال (بوابة النشر للإنتاج)، و**deployment branches** تمنع النشر إلا من `main`. تُربط بسطر `environment: production` داخل الوظيفة، وعندها تُقرأ أسرار البيئة بدل أسرار المستودع.

التقنيع يغطي القيمة الحرفية فقط. إن رمّزت السرّ (base64) أو قسّمته أو أدخلته في JSON مُصاغ، فقد يظهر نصاً صريحاً. ولا تمرّر سرّاً في `run` عبر الاستيفاء المباشر داخل صدفة — مرّره عبر `env` ثم استعمله كمتغيّر بيئة.

**الأسرار لا تصل إلى سير عمل يُشغَّل من fork عبر `pull_request`** — قيد أمني مقصود، وسبب فشل نشر PR خارجي دائماً.

## permissions وأقل امتياز

`GITHUB_TOKEN` يُولَّد لكل تشغيل وينتهي بانتهائه. اجعل الافتراضي في أعلى الملف `contents: read`، وارفع الصلاحية على الوظيفة المحتاجة وحدها:

```yaml
jobs:
  release:
    permissions:
      contents: write        # لإنشاء وسم أو إصدار
      id-token: write        # للمصادقة بلا مفتاح (OIDC) نحو مزوّد سحابي
```

اضبط الافتراضي على مستوى المستودع من Settings ← Actions ← Workflow permissions إلى Read repository contents. سير عمل بصلاحية كتابة كاملة + إجراء طرف ثالث غير مثبَّت = طريق مباشر لتعديل مستودعك.

## التبعية بين الوظائف

```yaml
  deploy:
    needs: test
    if: github.ref == 'refs/heads/main' && github.event_name == 'push'
```

`needs` يُنشئ الترتيب ويمرّر المخرجات: الوظيفة المُنتِجة تُعلن `outputs` تُشتقّ من خطوة كتبت قيمتها إلى `$GITHUB_OUTPUT`، وتُقرأ في التالية بـ `${{ needs.test.outputs.version }}`. والوظيفة التالية تُتخطّى تلقائياً عند فشل سابقتها إلا مع `if: always()` — استعملها لوظيفة تنظيف أو إشعار فقط.

## إعادة التشغيل وقراءة الفشل

من الجوال: Actions ← التشغيل الفاشل ← Re-run. خياران: **Re-run all jobs** و**Re-run failed jobs** — الثاني يوفّر الدقائق ويكفي لفشل عابر (شبكة، سجلّ حزم بطيء). و**Enable debug logging** عند إعادة التشغيل يشغّل السجلّ التفصيلي (يعادل ضبط `ACTIONS_STEP_DEBUG` بقيمة `true`).

ترتيب التشخيص: افتح **أول** خطوة حمراء لا آخر واحدة — الفشل يتسلسل. ابحث في السجلّ عن `Error:` و`##[error]`. ثم صنّف:

| العرَض | السبب الغالب |
|---|---|
| يعمل عندي ويفشل في CI | تبعية غير مثبَّتة، أو ملف غير ملتزَم، أو متغيّر بيئة ناقص |
| فشل متقطّع بلا تغيير كود | مهلة شبكة أو اختبار يعتمد على التوقيت |
| `command not found` | خطوة setup ناقصة قبله |
| فشل بعد إضافة cache | مفتاح بلا بصمة ملف القفل |
| السجلّ يتوقّف فجأة | نفاد الذاكرة على الـ runner |

اقرأ السجلّ **قبل** تعديل الكود. تخمين الإصلاح ودفعه لرؤية النتيجة يكلّفك دورة كاملة في كل مرة.

## الحدود والتكلفة

| البند | القيمة |
|---|---|
| مستودع عام | دقائق مجانية بلا حدّ |
| مستودع خاص (خطة Free) | 2000 دقيقة/شهر + 500 MB تخزين |
| مضاعف الاستهلاك | Linux ×1، Windows ×2، macOS ×10 |
| أقصى مدة وظيفة / تشغيل كامل | 6 ساعات / 35 يوماً |
| وظائف متزامنة (Free) | 20 |

macOS ×10 هو البند الذي يفجّر الحصّة: 20 دقيقة على macOS = 200 دقيقة من الحصّة. أبقِ كل ما يمكن على `ubuntu-latest`، واجعل مستودعاتك الشخصية عامة متى أمكن، وراقب الاستهلاك من Settings ← Billing. عند نفاد الحصّة في مستودع خاص **تتوقّف كل الأتمتة فجأة** — وهذا يعني توقف جهاز بنائك الوحيد. توفير عملي: `concurrency` مع الإلغاء، `paths-ignore` لتجاهل تعديلات التوثيق، تخزين مؤقت للتبعيات، ومصفوفة بأقل عدد تركيبات مفيد.

## قائمة تحقق

- [ ] كل سير عمل فيه `permissions: contents: read` على الأعلى ورفع صريح عند الحاجة
- [ ] `concurrency` مع `cancel-in-progress` و`timeout-minutes` على كل وظيفة
- [ ] `workflow_dispatch` موجود في كل سير عمل نشر، والملف على الفرع الافتراضي
- [ ] الإجراءات مثبَّتة على وسم رئيسي، وإجراءات الطرف الثالث على SHA
- [ ] تخزين مؤقت مفعّل ومفتاحه يحوي بصمة ملف القفل
- [ ] `upload-artifact` معه `if-no-files-found: error` و`retention-days` قصيرة
- [ ] الأسرار تُمرَّر عبر `env` لا داخل نصوص الصدفة، ولا `echo` لأي سرّ
- [ ] بيئة `production` عليها required reviewer وتقييد على فرع `main`
- [ ] استهلاك الدقائق مُراجَع، ولا شيء على macOS إلا لضرورة
