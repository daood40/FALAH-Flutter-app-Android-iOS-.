# أداء الويب

مسار الويب — ليس Flutter. الانطباع لا يُعتد به: كل قرار هنا مربوط برقم يُقاس. جهاز أندرويد متوسط على شبكة 3G هو المرجع، لا حاسوب المطوّر.

## Core Web Vitals والأهداف الرقمية

| المؤشر | يقيس | جيد | يحتاج تحسين | ضعيف |
|---|---|---|---|---|
| **LCP** (Largest Contentful Paint) | متى يظهر أكبر عنصر مرئي | ≤ 2.5s | 2.5–4.0s | > 4.0s |
| **INP** (Interaction to Next Paint) | تأخر الاستجابة للتفاعل | ≤ 200ms | 200–500ms | > 500ms |
| **CLS** (Cumulative Layout Shift) | قفز التخطيط غير المتوقع | ≤ 0.1 | 0.1–0.25 | > 0.25 |

الهدف: تحقيق العتبة الجيدة عند **الشريحة المئوية 75** من المستخدمين الحقيقيين، لا في المتوسط. مؤشرات مساعدة للتشخيص: TTFB ≤ 800ms، وFCP ≤ 1.8s.

## LCP: من أين يأتي وكيف يُصلح

عنصر LCP عادة صورة البطل أو عنوان كبير. حلّل الزمن إلى أربعة أجزاء وعالج الأكبر:

| الجزء | العلاج |
|---|---|
| TTFB بطيء | كاش على الحافة (CDN)، استعلامات أسرع، تقليل إعادة التوجيه |
| تأخر اكتشاف المورد | `<link rel="preload">` للصورة، وتجنّب تحميلها عبر JS أو CSS |
| زمن تحميل المورد | صيغة أحدث (AVIF/WebP)، أبعاد صحيحة، ضغط |
| تأخر الرسم | إزالة CSS/JS الحاجبة، وتقليل العمل على الخيط الرئيسي |

قواعد صارمة:

- صورة LCP: **لا** `loading="lazy"`، بل `fetchpriority="high"` و`decoding="sync"`.
- لا خط ويب حاجب في مسار العنوان الرئيسي؛ استعمل `font-display: swap`.
- إعادة توجيه واحدة تكلف 200–600ms على الجوال؛ اجعل الروابط تشير للوجهة النهائية.
- الصور المحمّلة من داخل JS تُكتشف متأخرة جداً؛ ضعها في HTML.

## INP: تأخر التفاعل

INP يقيس أطول تأخّر بين ضغطة المستخدم وأول رسمة بعدها. السبب دائماً **الخيط الرئيسي مشغول**.

- أي مهمة JS أطول من **50ms** مهمة طويلة (long task). قسّمها.
- استعمل `scheduler.yield()` حيث توفّر، أو قسّم العمل الطويل على دفعات مع إعادة التحكم للمتصفح بين كل دفعة.
- انقل الحسابات الثقيلة (تشفير، تحليل ملفات كبيرة، معالجة صور) إلى Web Worker.
- في React: القوائم الطويلة تحتاج افتراضية (virtualization) فوق ~100 صف؛ رسم 2000 صف يقتل INP.
- `debounce` 300ms لحقل البحث و`throttle` لمعالجات التمرير.
- سكربتات الطرف الثالث (تحليلات، دردشة، إعلانات) أكبر مصدر مفاجئ لـ INP. حمّلها `defer` أو بعد التفاعل الأول.

## CLS: قفز التخطيط

| السبب | العلاج |
|---|---|
| صورة بلا أبعاد | `width` و`height` أو `aspect-ratio` على كل صورة وفيديو وإطار |
| خط ويب يستبدل الاحتياطي | `size-adjust` أو خط احتياطي قريب المقاييس + `font-display: swap` |
| محتوى يُحقن أعلى الصفحة | احجز المساحة مسبقاً بحد أدنى للارتفاع |
| إعلان أو بانر ديناميكي | حاوية بارتفاع ثابت |
| حالة تحميل بأبعاد مختلفة عن النتيجة | هيكل عظمي (skeleton) بنفس أبعاد المحتوى |

التحريك بـ `transform` لا يُحسب في CLS؛ تغيير `height` أو `top` يُحسب.

## ميزانية الأداء

اكتبها كأرقام، وافشل البناء عند تجاوزها:

| البند | الميزانية (صفحة عادية) |
|---|---|
| JS بعد الضغط (gzip/br) | ≤ 170KB للمسار الحرج |
| CSS بعد الضغط | ≤ 50KB |
| صورة البطل | ≤ 150KB |
| وزن الصفحة الكلي | ≤ 1MB |
| عدد الطلبات عند التحميل الأول | ≤ 50 |
| الخطوط | ملفان كحد أقصى، `woff2` فقط |

في السياق الليبي والعربي عموماً حيث الشبكات متفاوتة، اعتبر هذه حدوداً عليا لا أهدافاً. كل 100KB إضافية من JS تكلف ~1s تنفيذاً على جهاز متوسط.

## الصور

- الترتيب: AVIF ← WebP ← JPEG/PNG احتياطياً عبر `<picture>`.
- AVIF أصغر من JPEG بنحو 50% بجودة مماثلة؛ WebP بنحو 30%.
- لا ترسل صورة أعرض من ضعف عرض العرض الفعلي. صورة 2400px في مساحة 400px هدر صافٍ.
- `srcset` + `sizes` إلزاميان لأي صورة متغيّرة الحجم.
- `loading="lazy"` لكل ما تحت الطية، و`decoding="async"`.
- SVG للأيقونات والشعارات، مع تنظيفه (SVGO) — ملفات المصمّم قد تكون 10× حجمها اللازم.
- لا صور PNG للصور الفوتوغرافية.

## الخطوط

```html
<link rel="preload" href="/fonts/arabic.woff2" as="font"
      type="font/woff2" crossorigin>
```

```css
@font-face {
  font-family: "Arabic UI";
  src: url("/fonts/arabic.woff2") format("woff2");
  font-display: swap;
  font-weight: 400 700;      /* خط متغيّر: ملف واحد لكل الأوزان */
  unicode-range: U+0600-06FF, U+0750-077F, U+FB50-FDFF, U+FE70-FEFF;
}
```

- `woff2` فقط؛ الصيغ الأقدم لم تعد ضرورية.
- `crossorigin` إلزامية مع `preload` للخطوط وإلا حُمّل الملف مرتين.
- `font-display: swap` يظهر النص فوراً بخط احتياطي — أفضل من نص غير مرئي (FOIT).
- الخطوط العربية أثقل من اللاتينية بطبيعتها (محارف وأشكال اتصال أكثر): استعمل خطاً متغيّراً واحداً بدل 4 ملفات أوزان، وقسّم النطاق بـ `unicode-range` بين العربي واللاتيني.
- الخط الاحتياطي يجب أن يكون قريب العرض من الأصلي وإلا قفز التخطيط عند التبديل.

## تقسيم الحزمة والاستيراد الديناميكي

```js
const Chart = React.lazy(() => import("./Chart"));       // مكوّن ثقيل
async function exportPdf() {                              // مكتبة عند الحدث
  const { jsPDF } = await import("jspdf");
}
```

- قسّم على مستوى **المسار** أولاً (أكبر مكسب)، ثم على مستوى المكوّنات الثقيلة (محرر نصوص، مخططات، خرائط، مُصدِّر PDF).
- كل `React.lazy` يحتاج `<Suspense>` بواجهة احتياطية لها نفس الأبعاد تقريباً (وإلا CLS).
- افحص الحزمة بمحلّل حجم (`rollup-plugin-visualizer` أو ما يعادله) قبل التحسين — غالباً 60% من الحجم في مكتبتين.
- استبدل المكتبات الثقيلة: `date-fns` أو `Intl` بدل مكتبات تواريخ ضخمة، واستورد الدوال المفردة لا الحزمة كاملة.
- `<link rel="modulepreload">` أو تحميل مسبق عند المرور (`hover`) للمسارات المتوقعة يخفي زمن التقسيم.

## التخزين المؤقت وترويسات الكاش

| نوع المورد | الترويسة |
|---|---|
| أصول ببصمة في الاسم (`app.9f3a.js`) | `Cache-Control: public, max-age=31536000, immutable` |
| HTML | `Cache-Control: no-cache` (يتحقق دائماً) |
| استجابة API قابلة للتخزين | `max-age=60, stale-while-revalidate=300` |
| محتوى خاص بالمستخدم | `private, no-store` |

- البصمة في اسم الملف هي ما يجعل الكاش الأبدي آمناً؛ بلا بصمة لا تستعمل `immutable` أبداً.
- `stale-while-revalidate` يعطي استجابة فورية من الكاش ويحدّث في الخلفية — مثالي للشبكات البطيئة.
- ضع CDN أمام كل شيء ثابت. التوجيه من ليبيا إلى خادم أوروبي يضيف 60–120ms لكل طلب؛ الحافة تلغي معظمها.
- Service Worker يفيد للعمل دون اتصال لكنه يضيف تعقيد إصدارات؛ لا تضفه بلا حاجة واضحة.

## عرض الخادم مقابل العميل

| الأسلوب | LCP | مناسب لـ |
|---|---|---|
| ثابت مسبق (SSG) | الأفضل | صفحات تسويقية، مدونة، توثيق |
| عرض خادم (SSR) | جيد | محتوى شخصي متغيّر، صفحات تحتاج فهرسة |
| عرض عميل (CSR/SPA) | الأسوأ للتحميل الأول | لوحات تحكم خلف تسجيل دخول |
| تدفّق + hydration جزئي | جيد جداً | صفحات مختلطة كبيرة |

- التطبيق أحادي الصفحة يعني شاشة بيضاء حتى ينزل JS ويُنفَّذ ويُجلب البيانات — ثلاث رحلات متتابعة.
- القاعدة: كل ما يجب أن يُفهرس أو يُفتح من رابط مشارَك يُعرض من الخادم.
- `hydration` ليس مجانياً؛ قلّل المكوّنات التفاعلية إلى ما يحتاج تفاعلاً فعلاً.

## القياس بأدوات حقيقية

| الأداة | ماذا تعطي |
|---|---|
| Lighthouse / PageSpeed Insights | فحص مخبري + بيانات ميدانية إن توفرت |
| Chrome DevTools > Performance | تحليل المهام الطويلة وسبب INP |
| `web-vitals` (حزمة npm) | قياس ميداني حقيقي من مستخدميك وإرساله لتحليلاتك |
| محلّل الحزمة | من أين يأتي الحجم |
| تقييد الشبكة والمعالج في DevTools | محاكاة جهاز متوسط (4× CPU slowdown, Slow 4G) |

قاعدتان: (1) قِس قبل التحسين وبعده، وسجّل الرقمين. (2) البيانات المخبرية تشخّص، والبيانات الميدانية تحكم — درجة Lighthouse 95 مع INP ميداني 400ms تعني أن المشكلة عند المستخدمين لا في المعمل.

## أخطاء شائعة

- التحسين بالحدس بلا قياس، وتحسين ما ليس اختناقاً.
- `loading="lazy"` على صورة البطل فيتأخر LCP.
- إضافة سكربتات طرف ثالث بلا `defer` ثم استغراب INP.
- الحكم من حاسوب المطوّر على شبكة سريعة.
- استيراد مكتبة كاملة لاستعمال دالة واحدة.
- كاش أبدي على ملف بلا بصمة، فلا يرى المستخدم التحديث.
- خطوط ويب متعددة الأوزان في مشروع عربي، فتتضاعف الأحجام.
- `useMemo` في كل مكان كـ "تحسين" بينما المشكلة في حجم الحزمة.

> أداء تطبيق Flutter مختلف كلياً؛ افتح flutter-performance.

## قائمة تحقق

- [ ] LCP ≤ 2.5s وINP ≤ 200ms وCLS ≤ 0.1 عند الشريحة 75 من المستخدمين الحقيقيين
- [ ] صورة LCP في HTML مع `fetchpriority="high"` وبلا `lazy`
- [ ] كل صورة/فيديو/إطار له أبعاد أو `aspect-ratio`
- [ ] الصور بصيغة AVIF/WebP مع `srcset` و`sizes`، والأبعاد مناسبة للعرض الفعلي
- [ ] خط متغيّر واحد `woff2` مع `font-display: swap` و`preload` + `crossorigin`
- [ ] ميزانية JS ≤ 170KB مضغوطة للمسار الحرج، ومفحوصة بمحلّل حزمة
- [ ] تقسيم على مستوى المسارات + استيراد ديناميكي للمكوّنات الثقيلة
- [ ] لا مهمة JS تتجاوز 50ms، والعمل الثقيل في Web Worker
- [ ] سكربتات الطرف الثالث مؤجّلة أو محمّلة بعد التفاعل
- [ ] كاش `immutable` للأصول المبصومة و`no-cache` لـ HTML، وCDN أمام الثابت
- [ ] ما يحتاج فهرسة يُعرض من الخادم
- [ ] القياس تم على جهاز متوسط مع تقييد الشبكة، والأرقام مسجّلة قبل وبعد
