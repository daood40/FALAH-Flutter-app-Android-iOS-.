# أساسيات React الحديثة

مسار الويب — ليس Flutter. المبدأ المركزي: **الواجهة دالة من الحالة**. كل شيء آخر تفصيل.

## المكوّنات والخصائص

- المكوّن دالة تستقبل `props` وتُعيد JSX. الاسم يبدأ بحرف كبير وإلا عومل كوسم HTML.
- `props` للقراءة فقط. تعديل كائن قادم من الأب خطأ صامت.
- المكوّن يجب أن يكون **نقياً** أثناء الرسم: نفس المدخلات تعطي نفس المخرجات، ولا آثار جانبية (طلب شبكة، تعديل DOM، `Math.random()` في مسار الرسم).
- لا تعرّف مكوّناً داخل مكوّن آخر — سيُعاد إنشاؤه في كل رسمة وتضيع حالته بالكامل. هذا خطأ متكرر وأعراضه "الحقل يفقد التركيز عند كل حرف".

```jsx
function Price({ amount, currency = "LYD" }) {
  return <span dir="ltr">{new Intl.NumberFormat("ar-LY", {
    style: "currency", currency
  }).format(amount)}</span>;
}
```

الأرقام والعملات في واجهة عربية: استعمل `Intl.NumberFormat` ولفّها بـ `dir="ltr"` حتى لا ينقلب ترتيب الرقم والرمز.

## JSX

- `className` لا `class`، و`htmlFor` لا `for`.
- كل الأقواس المعقوفة تعني JavaScript: `{value}`. القيم `null`, `undefined`, `false` لا تُرسم.
- الشرط: `cond && <X/>` — لكن **احذر الرقم صفر**: `{items.length && <List/>}` ترسم `0` على الشاشة. استعمل `items.length > 0 && ...`.
- القوائم تُبنى بـ `map`، وأي عنصر مكرر يحتاج `key`.
- `<>...</>` للتجميع بلا عنصر إضافي في DOM.

## الحالة المحلية

```jsx
const [count, setCount] = useState(0);
setCount(c => c + 1);   // دالة تحديث عند الاعتماد على القيمة السابقة
```

قواعد:

- الحالة **لقطة** لا متغيّر حي. قراءة `count` مباشرة بعد `setCount` تعطي القيمة القديمة في نفس الدالة.
- التحديث غير متزامن ويُدمج (batched). استدعاء `setCount(count+1)` ثلاث مرات يزيد واحداً؛ `setCount(c=>c+1)` ثلاث مرات يزيد ثلاثة.
- لا تعدّل الحالة مكاناً: `arr.push(x)` خطأ، `setArr([...arr, x])` صحيح. ونفس القاعدة للكائنات.
- أقل حالة ممكنة: كل ما يمكن اشتقاقه من حالة موجودة **يُحسب أثناء الرسم**، لا يُخزَّن.

```jsx
// خطأ: حالة مكرّرة تحتاج مزامنة
const [items, setItems] = useState([]);
const [count, setCount] = useState(0);

// صحيح: اشتقاق
const count = items.length;
const visible = items.filter(i => i.active);
```

## useEffect ومتى لا تحتاجه — الخطأ الأكبر

`useEffect` وُجد **للتزامن مع نظام خارج React**: اشتراك، مؤقّت، مستمع أحداث، واجهة متصفح، مكتبة غير React. ليس لتنسيق البيانات ولا لرد فعل على ضغطة.

| ما تريده | الأداة الصحيحة |
|---|---|
| قيمة مشتقّة من props أو state | احسبها أثناء الرسم |
| حساب ثقيل مشتق | `useMemo` بعد إثبات البطء بالقياس |
| رد فعل على حدث مستخدم | ضعه داخل معالج الحدث |
| إعادة ضبط حالة عند تغيّر عنصر | `key` مختلف على المكوّن |
| جلب بيانات من الخادم | مكتبة استعلام (TanStack Query) أو إطار العمل |
| تعديل حالة الأب بعد تغيّر حالة الابن | ارفع الحالة أو مرّر callback |
| اشتراك/إلغاء اشتراك، مؤقّت، مستمع | `useEffect` ✅ |

```jsx
// خطأ شائع: مزامنة يدوية تسبب رسمة زائدة ووميضاً
useEffect(() => { setFullName(first + " " + last); }, [first, last]);

// صحيح
const fullName = first + " " + last;
```

قواعد عند استعماله فعلاً:

- مصفوفة الاعتماديات كاملة وصادقة. حذف اعتمادية "لإسكات التحذير" يخلق أخطاء لا تُعاد.
- كل اشتراك يُنظَّف في دالة الإرجاع، وإلا تسرّبت المستمعات.
- الطلبات المتزامنة تحتاج إلغاءً (`AbortController`) أو علماً `ignore` لتجاهل استجابة قديمة وصلت متأخرة.
- في وضع التطوير الصارم يعمل الأثر مرتين عمداً؛ إن كسر ذلك شيئاً فالتنظيف ناقص.

## مفاتيح القوائم

```jsx
{orders.map(o => <OrderRow key={o.id} order={o} />)}
```

- المفتاح **معرّف ثابت من البيانات**. `key={index}` خطأ عند الحذف أو إعادة الترتيب أو الإدراج في المنتصف: React يعيد استعمال المكوّن الخطأ فتنتقل حالة الحقول لعنصر آخر.
- `index` مقبول فقط لقائمة ثابتة الترتيب لا تُضاف ولا تُحذف منها ولا تحتوي حالة داخلية.
- المفتاح فريد بين **الإخوة** فقط، ولا يُقرأ كـ prop داخل المكوّن.
- استعمال إضافي مهم: تغيير `key` على مكوّن يعيد ضبط حالته كلها — أنظف من `useEffect` لإعادة الضبط.

## رفع الحالة والتركيب

- إن احتاج مكوّنان نفس الحالة، ارفعها لأقرب أب مشترك ومرّرها مع دالة التغيير لأسفل.
- إن مرّت prop عبر 3+ مستويات بلا استخدام، فالحل عادة **التركيب** لا السياق:

```jsx
// بدل تمرير user عبر Layout ثم Sidebar ثم Profile
<Layout sidebar={<Profile user={user} />}>
  <Content />
</Layout>
```

- `children` وprops من نوع عنصر (`slot`) هما آلية إعادة الاستخدام في React. لا وراثة بين المكوّنات إطلاقاً.
- المنطق المشترك يُستخرج إلى **خطّاف مخصّص** (`useCart`, `useDebounced`) لا إلى مكوّن أساسي.

## المكوّنات المتحكّمة والنماذج

| متحكّم | غير متحكّم |
|---|---|
| `value` + `onChange` من الحالة | `defaultValue` وDOM يحتفظ بالقيمة |
| تحقق فوري، تعطيل زر، تنسيق أثناء الكتابة | نماذج بسيطة، ملفات، أداء أعلى |

- `value={x}` بلا `onChange` يجعل الحقل للقراءة فقط ويطبع تحذيراً.
- لا تنتقل من `undefined` إلى قيمة: `value={x ?? ""}` وإلا انقلب الحقل من غير متحكّم إلى متحكّم.
- للنماذج الكبيرة استعمل `react-hook-form` (غير متحكّم افتراضياً، أقل رسمات) مع `zod` للتحقق — بدل إدارة 15 `useState`.
- امنع الإرسال الافتراضي: `onSubmit={e => { e.preventDefault(); ... }}`، وعطّل الزر أثناء الإرسال لمنع التكرار.
- في العربية: التسميات مربوطة بـ `htmlFor`، ورسائل الخطأ نص واضح لا لون فقط.

## حدود الأخطاء (ErrorBoundary)

- خطأ أثناء الرسم يهدم الشجرة كلها ويترك شاشة بيضاء. حدّ الخطأ يلتقطه ويعرض بديلاً.
- يجب أن يكون **مكوّن صنف** (class) يستعمل `static getDerivedStateFromError` و`componentDidCatch`، أو استعمل حزمة `react-error-boundary` الجاهزة مع `<ErrorBoundary fallback={...} onReset={...}>`.
- لا يلتقط: أخطاء المعالجات (`onClick`)، الكود غير المتزامن، أخطاء الخادم. تلك تُعالج بـ `try/catch` وحالة خطأ صريحة.
- ضع حداً واحداً حول التطبيق وحدوداً أدق حول الأقسام المخاطرة (لوحة، مخطط، محرر) حتى لا يُسقط جزءٌ الصفحةَ كلها.

## قواعد الخطّافات

- تُستدعى في المستوى الأعلى من المكوّن أو من خطّاف مخصّص فقط — لا داخل شرط أو حلقة أو دالة متداخلة. الترتيب هو ما يربط الخطّاف بحالته.
- اسم الخطّاف المخصّص يبدأ بـ `use`.
- `useMemo` و`useCallback` أدوات أداء لا صحّة. لا تضعهما افتراضياً؛ أضفهما بعد قياس بطء فعلي.
- `useRef` لقيمة تبقى بين الرسمات ولا تسبب إعادة رسم: مؤقّت، عقدة DOM، قيمة سابقة.
- فعّل `eslint-plugin-react-hooks` — يمسك أغلب هذه الأخطاء آلياً.

## أخطاء شائعة

- `useEffect` لمزامنة حالة مشتقّة (السبب الأول للأخطاء والوميض).
- `key={index}` في قائمة قابلة للتغيير.
- تعريف مكوّن داخل مكوّن.
- تعديل الحالة مباشرة (`obj.x = 1` ثم `setObj(obj)`) — لا رسمة لأن المرجع لم يتغيّر.
- `{count && <X/>}` فيظهر `0`.
- تخزين قيمة يمكن اشتقاقها.
- حذف اعتماديات لإسكات ESLint.
- طلب شبكة في `useEffect` بلا إلغاء ولا حالة تحميل/خطأ.

> إدارة الحالة المتقدّمة (خادم/عميل/عنوان): افتح web-react-state.

## قائمة تحقق

- [ ] لا حالة مخزَّنة يمكن اشتقاقها أثناء الرسم
- [ ] كل `useEffect` موجود يتزامن مع نظام خارجي فعلاً، وله تنظيف
- [ ] لا اعتمادية محذوفة، و`eslint-plugin-react-hooks` مفعّل
- [ ] كل `key` معرّف ثابت من البيانات لا `index`
- [ ] لا مكوّن معرّف داخل مكوّن
- [ ] تحديثات الحالة غير مُعدِّلة للمكان (نسخ جديدة دائماً)
- [ ] الشروط المنطقية لا تسرّب `0` إلى الواجهة
- [ ] الحقول المتحكّمة لها `value` و`onChange`، ولا تبدأ بـ `undefined`
- [ ] النموذج يمنع الإرسال الافتراضي ويعطّل الزر أثناء الإرسال
- [ ] `ErrorBoundary` حول التطبيق وحول الأقسام المخاطرة
- [ ] `useMemo`/`useCallback` مضافان بعد قياس لا افتراضياً
- [ ] الأرقام والعملات عبر `Intl` وملفوفة بـ `dir="ltr"` داخل النص العربي
