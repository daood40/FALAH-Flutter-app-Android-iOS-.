# الجوانب القانونية والخصوصية عملياً

> **هذا ليس استشارة قانونية.** المحتوى هنا ممارسات عملية ومتطلبات متاجر معلنة. القوانين تختلف بحسب بلدك وبلد مستخدميك وتتغيّر باستمرار، والمتاجر تحدّث سياساتها دورياً. راجع نصوص السياسات الرسمية لكل متجر قبل كل إصدار، واستشر مختصاً قانونياً قبل إطلاق أي منتج يعالج بيانات مالية أو صحية أو بيانات أطفال.

> الجانب التقني للتشفير والتخزين الآمن: افتح مهارة flutter-security.

## المبدأ الحاكم: تقليل الجمع

أرخص طريقة للامتثال هي **ألا تجمع**. البيانات التي لا تملكها لا تُسرَّب، ولا تحتاج إعلانها، ولا تحتاج حذفها، ولا تُسأل عنها.

قبل كل حقل تجمعه، أجب كتابةً عن أربعة أسئلة: الغرض المحدد؟ الميزة التي تتعطل بدونه؟ مدة الاحتفاظ؟ هل يكفي أقل منه؟ إن لم تكن الإجابات جاهزة، احذف الحقل. قاعدة عملية: **أي حقل لا يُستخدم في أول 30 يوماً من عمر المنتج، لا يُجمَع**.

أمثلة على تقليل حقيقي:
- الموقع الدقيق ← اسم المدينة يكفي في أغلب الحالات.
- جهات الاتصال كاملة ← إدخال رقم واحد يدوياً.
- الصورة الأصلية بكامل بياناتها الوصفية ← صورة مضغوطة بعد إزالة بيانات EXIF ومنها الموقع.
- تاريخ ميلاد كامل ← تأكيد «أكبر من 18» فقط إن كان هذا هو الغرض.

## سياسة الخصوصية: ما يجب أن تحتويه فعلاً

سياسة منسوخة من مولّد جاهز، تذكر خدمات لا تستخدمها وتغفل ما تستخدمه، **أسوأ من لا شيء** — لأنها تصبح تصريحاً غير مطابق أمام المتجر والمستخدم.

البنود الإلزامية عملياً:

| البند | المطلوب |
|---|---|
| هويتك | الاسم أو اسم الكيان + وسيلة تواصل تعمل |
| ما يُجمع | قائمة صريحة بالفئات: هوية، اتصال، محتوى، موقع، معرّفات جهاز، بيانات استخدام |
| لماذا | غرض محدد لكل فئة، لا «لتحسين الخدمة» وحدها |
| الأساس | موافقة المستخدم، أو ضرورة لتنفيذ الخدمة |
| مع من يُشارَك | أسماء الأطراف الفعلية (مزوّد الاستضافة، التحليلات، تتبّع الأعطال، مزوّد الرسائل) |
| أين يُخزَّن | البلد/المنطقة التي تعمل بها خوادمك |
| كم يُحتفظ به | مدة محددة لكل فئة |
| حقوق المستخدم | الاطلاع، التصحيح، التصدير، الحذف، سحب الموافقة — مع **كيفية** ممارستها |
| الأطفال | حدّك العمري وما تفعله عند اكتشاف مستخدم أصغر |
| الإشعار بالتغيير | كيف تُخطر المستخدمين، وتاريخ آخر تحديث ظاهر |
| قناة الشكاوى | بريد أو رقم يُرَد عليه |

قواعد الصياغة:
- **بالعربية** أولاً وبلغة مفهومة؛ إن كان لديك مستخدمون بلغات أخرى فوفّر نسخة مطابقة.
- **رابط عام يعمل بلا تسجيل** — يُفحص من فريق المراجعة. الرابط المعطّل سبب رفض شائع.
- الرابط موجود في **صفحة المتجر وداخل التطبيق** (الإعدادات) وقبل التسجيل.
- كل مرة تضيف SDK أو خدمة جديدة، **حدّث السياسة والنموذج في نفس الإصدار**.

## شروط الاستخدام

مطلوبة عملياً لأي منتج فيه حسابات أو محتوى من المستخدمين أو دفع. البنود الأساسية:

- من يحق له الاستخدام (السن الأدنى، النطاق الجغرافي).
- الاستخدامات الممنوعة، وحقك في تعليق أو حذف الحساب المخالف.
- ملكية المحتوى: **المحتوى ملك للمستخدم**، وتأخذ ترخيصاً محدوداً لعرضه وتشغيل الخدمة فقط.
- الدفع والاسترداد والإلغاء بشروط واضحة إن كان هناك مقابل مالي.
- حدود المسؤولية، وأن الخدمة تُقدَّم «كما هي» بلا ضمان توافر مطلق.
- إنهاء الخدمة: ماذا يحدث لبياناتهم إن أغلقت المنتج، وكم مهلة التصدير (مثلاً 30 يوماً).
- القانون الواجب التطبيق وجهة فض النزاع.
- إجراء الإبلاغ والحظر إن كان هناك محتوى من المستخدمين، ومدة استجابتك.

## نموذج سلامة البيانات وتسميات الخصوصية

| | Google Play | App Store |
|---|---|---|
| الاسم | Data safety | App Privacy (تسميات الخصوصية) |
| المطلوب | إعلان ما تجمعه وتشاركه، والغرض، وهل مشفّر أثناء النقل، وهل يمكن طلب الحذف | إعلان البيانات المجمّعة وربطها بالهوية واستخدامها في التتبّع |
| ATT | — | تتبّع المستخدم عبر تطبيقات وشركات أخرى يتطلب إذن **App Tracking Transparency** صراحةً |

قواعد إلزامية:
- **يشمل ما تجمعه المكتبات وليس كودك فقط.** تحليلات، تتبّع أعطال، خرائط، إعلانات، إشعارات — كلها تجمع بيانات ويجب إعلانها.
- اصنع جدولاً بكل SDK في المشروع وما يجمعه، وحدّثه مع كل إضافة:

```yaml
sdks:
  - { name: الاستضافة/قاعدة البيانات, collects: [حساب المستخدم, المحتوى المُدخل, IP] }
  - { name: تتبّع الأعطال, collects: [معرّف جهاز, نسخة النظام, سجل العطل] }
  - { name: التحليلات, collects: [أحداث الاستخدام, معرّف مجهول, بلد تقريبي] }
  - { name: الإشعارات, collects: [رمز الجهاز للإشعار] }
```

- **عدم المطابقة بين الإعلان والواقع من أكثر أسباب الرفض والإزالة.** فريق المراجعة يفحص حركة الشبكة فعلياً.
- «لا نجمع أي بيانات» تصريح شبه مستحيل الصحة إن كنت تستخدم حساباً أو تحليلات أو تتبّع أعطال.

## موافقة المستخدم ومتى تُطلب

| الحالة | المطلوب |
|---|---|
| بيانات ضرورية لتشغيل الخدمة (الحساب، المحتوى الذي أدخله) | إخطار في السياسة، لا نافذة موافقة منفصلة |
| الموقع، الكاميرا، جهات الاتصال، الإشعارات | إذن نظام **في سياق الاستخدام** مع تمهيد يشرح المقابل |
| التتبّع الإعلاني عبر تطبيقات أخرى (iOS) | نافذة ATT إلزامية قبل الوصول للمعرّف الإعلاني |
| التحليلات لمستخدمين في الاتحاد الأوروبي | موافقة مسبقة صريحة قابلة للسحب |
| بيانات حساسة (صحية، مالية، بيومترية) | موافقة صريحة منفصلة، وتجنّبها ما لم تكن جوهر المنتج |
| مشاركة البيانات مع طرف ثالث لأغراضه | موافقة صريحة، ولا تُفترض أبداً |

قواعد:
- **الموافقة المسبقة المؤشّرة تلقائياً ليست موافقة.** خانة الاختيار تبدأ فارغة.
- سحب الموافقة يجب أن يكون بنفس سهولة منحها، ومن داخل الإعدادات.
- لا تربط استخدام المنتج بموافقة على شيء غير ضروري لتشغيله.
- سجّل **تاريخ ونسخة** السياسة التي وافق عليها كل مستخدم.

## حذف الحساب والبيانات — متطلب إلزامي

المتجران يشترطان: **إن كان التطبيق يسمح بإنشاء حساب، فيجب أن يسمح بحذفه**.

- **داخل التطبيق**: مسار واضح في الإعدادات، لا يزيد عن 2–3 خطوات، بلا مطالبة بمراسلة الدعم.
- **عبر الويب**: Google Play يشترط أيضاً **رابطاً خارجياً** يمكن الوصول إليه بلا تثبيت التطبيق، ويُدخَل في صفحة المتجر.
- الحذف يشمل البيانات المرتبطة بالحساب، لا تعطيل الحساب فقط.
- يجوز الاحتفاظ بما يفرضه قانون أو ضرورة مشروعة (سجلات معاملات مالية مثلاً) — **وهذا يُذكَر صراحةً للمستخدم**.
- أتِح **حذفاً جزئياً** حيث يكون منطقياً (حذف محتوى دون الحساب).
- الممارسة السليمة: تأكيد + مهلة استرجاع 7–30 يوماً معلنة، ثم حذف فعلي، مع رسالة تأكيد بعد التنفيذ.
- وفّر **تصدير البيانات** قبل الحذف — حق أخلاقي، ومطلوب في بعض الولايات القضائية.
- اختبر المسار كاملاً قبل كل إطلاق؛ مسار حذف مكسور سبب رفض وسبب شكوى.

## بيانات الأطفال

هذا أخطر مجال على الإطلاق. القاعدة الآمنة: **إن لم يكن منتجك موجّهاً للأطفال، فامنعهم صراحةً وتجنّب جمع أي بيانات منهم.**

- حدّد سناً أدنى في الشروط (18 عادةً للمنتجات المالية، و13 كحد أدنى شائع لغيرها) واذكره في السياسة.
- في الولايات المتحدة تُطبَّق قواعد خاصة على من هم دون **13**؛ وفي الاتحاد الأوروبي حد الموافقة يتراوح بين **13 و16** بحسب الدولة. إن كان لديك مستخدمون هناك فالمسألة ليست اختيارية.
- إن كان المنتج موجّهاً للأطفال أو لجمهور مختلط: يخضع لسياسات إضافية في المتجرين (برامج العائلة/فئة الأطفال)، ويُمنع فيه التتبّع الإعلاني والإعلانات السلوكية، وتُقيَّد المكتبات المسموح بها.
- عند اكتشاف حساب لمستخدم أقل من الحد: عطّل الحساب واحذف بياناته، واذكر هذا الإجراء في السياسة.
- **لا تجمع تاريخ ميلاد كامل** لمجرد التحقق من السن؛ سؤال تأكيدي أو سنة الميلاد يكفي غالباً.

## الاحتفاظ بالبيانات ومددها

اكتب جدول احتفاظ صريحاً واعمل به فعلياً؛ الجدول غير المنفَّذ التزام مكشوف.

| نوع البيانات | مدة معقولة |
|---|---|
| حساب نشط | ما دام الحساب قائماً |
| حساب محذوف | حذف خلال 30 يوماً كحد أقصى بعد انتهاء مهلة الاسترجاع |
| حساب خامل بلا نشاط | إخطار عند 12 شهراً، حذف أو أرشفة عند 24 شهراً |
| سجلات الخوادم و IP | 30–90 يوماً |
| تقارير الأعطال | 90 يوماً |
| أحداث التحليلات | 12–24 شهراً، ومجهولة الهوية بعدها |
| سجلات الدفع والفواتير | بحسب الإلزام المحاسبي في بلدك — عادة سنوات، وتُذكر صراحةً |
| نسخ احتياطية | دورة استبدال معلنة (مثلاً 30 يوماً) يُذكر أن الحذف يسري عليها ضمنها |

> تنفيذ النسخ الاحتياطي والاستعادة: افتح مهارة data-backup-recovery.

## معالجة البيانات لدى أطراف ثالثة

كل خدمة تستضيف أو تمرّ بها بيانات مستخدميك هي **معالج بالنيابة عنك**، وأنت المسؤول أمام المستخدم.

قبل إضافة أي خدمة، أجب: ما البيانات التي تصلها بالضبط؟ في أي بلد تُخزَّن؟ هل توفّر اتفاقية معالجة بيانات (DPA)؟ هل تستخدم بياناتك لأغراضها الخاصة؟ ماذا يحدث للبيانات عند إنهاء الاشتراك؟ وهل أُعلنت في سياستك ونموذج المتجر؟

قواعد:
- اذكر الأطراف **بالفئة أو بالاسم** في السياسة، وحدّث القائمة عند كل تغيير.
- **لا ترسل بيانات شخصية إلى خدمات ذكاء اصطناعي أو تحليلات خارجية** بلا إعلان وموافقة صريحين؛ وأزل ما يمكن إزالته قبل الإرسال.
- انتبه لمنطقة الخوادم: نقل بيانات مستخدمين أوروبيين خارج المنطقة له شروط.
- قلّل عدد الأطراف: كل خدمة إضافية تعني بنداً في السياسة، وسطراً في نموذج المتجر، وخطراً أمنياً إضافياً.

## ملاحظة عن السياق المحلي

- في ليبيا لا يوجد إطار شامل ونافذ لحماية البيانات الشخصية مماثل للأطر الأوروبية، ولا يعني ذلك غياب المسؤولية: **سياسات المتجرين تُطبَّق عليك بغض النظر عن بلدك**، وقوانين بلد المستخدم قد تنطبق عليك إن خدمته — فإن كان بين مستخدميك أوروبيون أو أمريكيون فالأطر هناك قد تسري ولو كنت في ليبيا.
- قوانين المنطقة تتغيّر بسرعة (السعودية والإمارات ومصر وغيرها أصدرت أطراً لحماية البيانات). تحقّق من وضع كل سوق تدخله.
- إن كان المنتج يعالج مدفوعات أو بيانات صحية أو بيانات أطفال، فالمراجعة القانونية قبل الإطلاق ليست اختيارية.

## أخطاء شائعة

- نسخ سياسة خصوصية من قالب يذكر خدمات لا تستخدمها ويغفل ما تستخدمه.
- ملء نموذج سلامة البيانات على عجل بـ«لا نجمع بيانات» مع وجود تحليلات وتتبّع أعطال.
- نسيان حذف الحساب حتى يوم الرفض، أو تنفيذه داخل التطبيق فقط دون رابط ويب.
- «حذف» يعني تعطيلاً فقط مع بقاء البيانات كاملة.
- إضافة SDK جديد بلا تحديث السياسة ونموذج المتجر في نفس الإصدار.
- جمع الموقع الدقيق أو جهات الاتصال بلا حاجة فعلية، أو تخزين صور المستخدمين ببيانات EXIF التي تحوي موقع التقاطها.
- خانة موافقة مؤشّرة مسبقاً، أو موافقة واحدة تغطي كل شيء إلى الأبد، أو غياب مسار لسحب الموافقة.
- جدول احتفاظ مكتوب في السياسة ولا يُنفَّذ فعلياً في قاعدة البيانات.
- شروط استخدام تمنح نفسك ملكية محتوى المستخدم — يهدم الثقة ويعرّضك قانونياً.
- إرسال بيانات المستخدمين إلى خدمة خارجية للتجريب بلا إعلان، أو إغلاق منتج بلا مهلة تصدير معلنة.

## قائمة تحقق

- [ ] لكل حقل مجموع: غرض محدد، ميزة تتعطل بدونه، ومدة احتفاظ مكتوبة
- [ ] كل حقل بلا استخدام فعلي محذوف من التطبيق ومن قاعدة البيانات
- [ ] سياسة الخصوصية بالعربية، على رابط عام يعمل، وداخل التطبيق وفي صفحة المتجر
- [ ] السياسة تذكر الأطراف الفعلية، مكان التخزين، مدد الاحتفاظ، وحقوق المستخدم وكيفية ممارستها
- [ ] شروط الاستخدام تغطي السن، الاستخدامات الممنوعة، ملكية المحتوى للمستخدم، والدفع والاسترداد
- [ ] جدول SDK ← ما يجمعه، محدَّث، ومطابق لنموذج سلامة البيانات وتسميات الخصوصية
- [ ] لا يوجد أي تصريح غير مطابق للواقع في نماذج المتجرين
- [ ] نافذة ATT مطبّقة إن وُجد أي تتبّع عبر تطبيقات أخرى على iOS
- [ ] الأذونات تُطلب في سياقها، وخانات الموافقة تبدأ فارغة، والسحب متاح من الإعدادات
- [ ] حذف الحساب متاح داخل التطبيق (≤ 3 خطوات) **وعبر رابط ويب** ومختبَر فعلياً
- [ ] تصدير البيانات متاح قبل الحذف، والاستثناءات القانونية مذكورة صراحةً
- [ ] السن الأدنى معلن، وإجراء اكتشاف مستخدم أصغر منه مكتوب ومنفَّذ
- [ ] جدول الاحتفاظ منفَّذ فعلياً، ويشمل النسخ الاحتياطية بمدة معلنة
- [ ] قائمة الأطراف المعالِجة مراجَعة، ولا بيانات شخصية تُرسل لأي خدمة خارجية بلا إعلان
- [ ] السياسات تُراجَع مع كل إصدار يضيف بيانات أو خدمة، ومراجعة قانونية مخططة إن كان المنتج يعالج مدفوعات أو بيانات صحية أو بيانات أطفال
