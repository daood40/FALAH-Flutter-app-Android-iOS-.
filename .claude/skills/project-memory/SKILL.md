# ذاكرة المشروع

كل جلسة تبدأ من الصفر: النموذج لا يتذكّر ما قبلها، فيعيد اقتراح حل جُرِّب وفشل، أو يبني ميزة موجودة، أو يقول «تم الاختبار» عن اختبار لم يُشغَّل. الحل ليس محادثة أطول بل **ملفات داخل المستودع**.

> تجهيز `CLAUDE.md` والوكلاء والصلاحيات: افتح مهارة claude-code-project-setup.

## المحادثة ليست ذاكرة

| المحادثة | ملفات `memory/` |
|---|---|
| تُقتطع عند امتلاء نافذة السياق | تبقى كاملة |
| تنتهي بإغلاق الجلسة | تُقرأ في الجلسة القادمة |
| تخلط القرار بالتجربة بالكلام | مُصنَّفة، كل نوع في ملف، متتبَّعة في git |

القاعدة الحاكمة: **ما لم يُكتب في ملف مُتتبَّع في git فهو غير موجود.**

## البنية

مجلد `memory/` في جذر المستودع، مُتتبَّع في git (لا يدخل `.gitignore`)، markdown فقط.

| الملف | يحتوي | لا يحتوي |
|---|---|---|
| `PROJECT_MEMORY.md` | ما هو المشروع، المكدّس، حالة اليوم، أين توقّفنا | تفاصيل تقنية عميقة، قوائم مهام |
| `ARCHITECTURE.md` | الطبقات، تدفّق البيانات، حدود المسؤوليات | كود كامل، شرح مكتبات عامة |
| `DECISIONS.md` | ADR: القرار، البدائل، السبب، التاريخ | نقاش بلا قرار، تفضيلات ذوقية |
| `BUGS.md` | الأعطال المفتوحة بخطوات إعادة الإنتاج | ما أُصلح (يُنقل إلى FIXES) |
| `FIXES.md` | السبب الجذري والحل وقاعدة الوقاية | نسخة من سجل git |
| `FEATURES.md` | ما نُفِّذ وشُغِّل وتُحقِّق منه | ميزات مخطّطة أو نصف منجزة |
| `TODO.md` | المتبقي بأولويات P0/P1/P2 | أفكار بعيدة خارج قسم «لاحقاً» |
| `TEST_RESULTS.md` | آخر تشغيل حقيقي: التاريخ، الأمر، الأرقام | نتائج متوقَّعة أو مقدَّرة |
| `RELEASE.md` | الإصدار الحالي وما فيه وحالة المتجر | خطط تسويق |

## متى يُحدَّث كل ملف

| الحدث | يُحدَّث |
|---|---|
| قرار بنيوي أو اختيار حزمة أو تغيير مخطط | `DECISIONS.md` + `ARCHITECTURE.md` فوراً |
| اكتشاف عطل | `BUGS.md` لحظة الاكتشاف، لا نهاية الجلسة |
| إصلاح عطل | `FIXES.md` وحذف البند من `BUGS.md` معاً |
| اكتمال ميزة والتحقق منها | `FEATURES.md` + شطبها من `TODO.md` |
| تشغيل اختبار فعلي / رفع إصدار | `TEST_RESULTS.md` بتاريخ اليوم / `RELEASE.md` |
| نهاية كل جلسة | `PROJECT_MEMORY.md` + `TODO.md` |

**قاعدة الـcommit الواحد:** تحديث الذاكرة يدخل نفس الـcommit الذي أحدث التغيير، لا commit لاحق باسم «تحديث التوثيق» — المؤجَّل لا يحدث.

```bash
git add lib/features/cart/ memory/FIXES.md memory/BUGS.md
git commit -m "fix(cart): احتساب الشحن المجاني عند 200 د.ل"
```

## الحجم والاختصار

سقوف: `PROJECT_MEMORY.md` 60 سطراً (يُعاد كتابته من الصفر عند التجاوز)، `ARCHITECTURE.md` 120 سطراً (احذف الشرح وأبقِ القواعد)، `DECISIONS.md` 20 قراراً نافذاً، `FIXES.md` 40 إدخالاً. ما يتجاوز يُنقل إلى `memory/archive/decisions-2026.md` ولا يُحذف. الاختصار عملية مقصودة مع كل إصدار، وكل بند في `BUGS.md` و`TODO.md` سطران بحد أقصى.

## `memory/` مقابل `CLAUDE.md`

| | `CLAUDE.md` | `memory/` |
|---|---|---|
| النوع | قواعد ثابتة وأوامر وأسلوب | حالة متغيّرة ووقائع |
| التغيير | نادر | كل جلسة |
| مثال | «لا تستعمل setState في هذا المشروع» | «الشاشة الرئيسية تحوّلت إلى Riverpod أمس» |
| عند التعارض | يحكم في القاعدة | يحكم في الواقع |

الخطأ الأكثر شيوعاً هنا هو حشو `CLAUDE.md` بحالة اليوم فيتضخّم ويُقرأ في كل جلسة بلا فائدة. يكفي فيه سطر: «اقرأ `memory/PROJECT_MEMORY.md` و`TODO.md` و`BUGS.md` قبل أي عمل».

## طقس بداية الجلسة

1. `PROJECT_MEMORY.md` — أين نحن وأين توقّفنا.
2. `TODO.md` — ما أولوية P0 الأولى.
3. `BUGS.md` — هل ما سأبنيه فوق عطل مفتوح. ثم `DECISIONS.md` فقط إن كنت على وشك قرار بنيوي، لتجنّب إعادة فتح ما حُسم.
4. اذكر بسطر: «سأعمل على X، وسأتجنّب Y بسبب BUG-012». إن ناقضت الذاكرة الكود، **الكود هو الحقيقة** وصحّح الذاكرة قبل البدء.

## طقس نهاية الجلسة

خمس دقائق قبل آخر commit: اشطب المنجَز في `TODO.md` وأضف ما ظهر · انقل ما أُصلح إلى `FIXES.md` وسجّل ما اكتُشف في `BUGS.md` · سجّل الاختبار في `TEST_RESULTS.md` إن شُغِّل فقط · حدّث «الحالة اليوم» و«أين توقّفنا» · commit واحد يضم الكود والذاكرة.

اختبار الجودة: **لو فُتحت الجلسة القادمة بلا أي سياق، هل تكفي هذه الملفات للبدء خلال دقيقتين؟**

## منع الذاكرة من الكذب

ذاكرة تكذب أسوأ من لا ذاكرة، لأن الجلسات القادمة تبني عليها.

- لا تُكتب نتيجة اختبار لم يُشغَّل. «يُفترض أن ينجح» ليس نتيجة؛ اكتب «لم يُشغَّل — يحتاج جهازاً أو Actions».
- لا تدخل ميزة `FEATURES.md` قبل تشغيلها ورؤيتها تعمل. الكود المكتوب ليس ميزة منجَزة، و«مكتمل جزئياً» يبقى في `TODO.md`.
- كل بند في `TEST_RESULTS.md` و`RELEASE.md` بتاريخ؛ بند بلا تاريخ يُعامَل منتهي الصلاحية.
- لا تُحذف قرارات ثبت خطؤها؛ اجعل حالتها «مُستبدَل بـ ADR-00X». معرفة ما فشل أثمن من إخفائه.
- الأرقام صريحة: «41 نجحت / 3 فشلت» لا «معظم الاختبارات تنجح». وعند الشك بين وصف متفائل وآخر دقيق، اكتب الدقيق — `memory/` ليست عرضاً تسويقياً.

## أخطاء شائعة

- إنشاء الملفات ثم إهمالها ثلاث جلسات؛ الذاكرة القديمة أخطر من الفارغة — تحقّق من التاريخ أولاً.
- وضع `memory/` في `.gitignore`، أو ملف واحد ضخم `NOTES.md` بدل التقسيم فلا يُقرأ ولا يُحدَّث.
- نسخ سجل git إلى `FIXES.md`؛ المطلوب السبب الجذري والوقاية لا قائمة commits.
- ADR لكل تفصيلة؛ القرار يستحق ADR إن كان عكسه مكلفاً لاحقاً. وفي المقابل: «أكملنا بعض العمل على السلة» كـ«أين توقّفنا» بلا معنى للجلسة القادمة.
