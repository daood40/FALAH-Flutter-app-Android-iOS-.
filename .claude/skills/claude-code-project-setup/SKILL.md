# تجهيز المستودع لكلود كود

مستودع مجهّز جيداً يجعل كل جلسة تبدأ من نقطة متقدمة بدل إعادة شرح نفس الأشياء.

## ملف CLAUDE.md — أهم ملف في المستودع

يُقرأ تلقائياً في بداية كل جلسة. اجعله **قصيراً وحاسماً**؛ الملف الطويل يُقصّ ويستهلك السياق.

### ماذا يوضع فيه

```markdown
# <اسم المشروع>

سطر واحد: ما هو المشروع ولمن.

## المكدّس
Flutter + Supabase. الحالة Riverpod، التنقل go_router.
النصوص كلها من ملفات الترجمة في `lib/l10n`.

## قواعد لا تُخالَف
- لا مفاتيح سرية في كود التطبيق إطلاقاً.
- الصلاحيات تُفرض في قواعد قاعدة البيانات، لا في الواجهة.
- كل شاشة لها أربع حالات: تحميل، فراغ، خطأ، بيانات.
- `EdgeInsetsDirectional` لا `left/right`.

## قبل أي push
dart format ثم flutter analyze ثم flutter test — لا تدفع أحمر.

## أسلوب العمل
- اعمل على فرع، لا على main.
- commit صغير برسالة تشرح السبب.
- لا تدّعِ نجاح بناء لم يُشغَّل فعلاً.

## مراجع
الحالة في `PROJECT_STATUS.md`، الخطة في `docs/ROADMAP.md`.
```

### ماذا لا يوضع فيه

- شرح ما يعرفه كلود أصلاً (ما هو Flutter، كيف يعمل git).
- توثيق طويل — ضعه في `docs/` وأشر إليه بسطر واحد.
- قوائم ملفات يمكن اكتشافها بالقراءة.
- تعليمات متناقضة تراكمت مع الوقت — راجعه كل شهر واحذف الميت منه.

### الأماكن التي يعيش فيها

| المكان | النطاق |
|---|---|
| `CLAUDE.md` في جذر المستودع | كل المشروع — يُرفع مع الكود |
| `<مجلد>/CLAUDE.md` | يُقرأ عند العمل داخل ذلك المجلد فقط |
| `~/.claude/CLAUDE.md` | كل مشاريعك على نفس الجهاز (سطر الأوامر فقط) |

في المستودع الكبير: ملف جذر قصير + ملف صغير في كل منطقة (`lib/features/auth/CLAUDE.md` مثلاً) أفضل بكثير من ملف واحد ضخم.

## مجلد المهارات `.claude/skills/`

مهارة = معرفة متخصصة تُقرأ **عند الحاجة فقط**، فلا تستهلك سياقاً حتى تُستدعى.

```
.claude/skills/
└── <اسم-المهارة>/
    └── SKILL.md
```

الصيغة:

```markdown
---
name: اسم-المهارة-بالإنجليزية-بشرطات
description: ماذا تغطي ومتى تُفتح، مع كلمات مفتاحية عربية وإنجليزية.
---

# المحتوى
```

قواعد تجعل المهارة تُستدعى فعلاً:
- `name` مطابق تماماً لاسم المجلد، حروف صغيرة وشرطات فقط.
- `description` هو ما يقرر الاستدعاء — ضع فيه **الكلمات التي سيكتبها المستخدم فعلاً** بالعربية والإنجليزية.
- المحتوى مركّز وقابل للتنفيذ، لا مقالة عامة.
- مهارة واحدة لموضوع واحد؛ مهارة تغطي كل شيء لا تُستدعى في وقتها الصحيح.

**متى تصنع مهارة:** إجراء تكرّر ثلاث مرات، أو قاعدة تشرحها في كل جلسة، أو معرفة تخصصية لمجال معيّن.

## الوكلاء الفرعيون `.claude/agents/`

وكيل معرّف مسبقاً لمهمة متكررة، بسياق منفصل وأدوات محددة.

```markdown
---
name: security-reviewer
description: يراجع التغييرات بعقلية مهاجم ويذكر الثغرات فقط. استدعِه قبل دمج أي تغيير يمسّ المصادقة أو الصلاحيات أو الدفع.
tools: Read, Grep, Glob
---

راجع التغييرات الحالية بحثاً عن: تجاوز الصلاحيات، مفاتيح مكشوفة،
اعتماد على فحص من جانب العميل، مدخلات غير موثوقة تصل لقاعدة البيانات.
اذكر كل ثغرة بموقعها وسيناريو استغلالها. لا تذكر ما هو سليم.
```

الأفضل عملياً: وكيل مراجعة أمنية، ووكيل بحث في المستودع، ووكيل كتابة اختبارات. اقصر `tools` على القراءة في وكلاء المراجعة حتى لا يعدّلوا شيئاً.

## الإعدادات والصلاحيات `.claude/settings.json`

يُرفع مع المستودع ويطبَّق على كل من يعمل فيه.

```json
{
  "permissions": {
    "allow": [
      "Bash(flutter *)",
      "Bash(dart *)",
      "Bash(git status)",
      "Bash(git diff*)"
    ],
    "deny": [
      "Read(./env/*.json)",
      "Read(./android/key.properties)",
      "Bash(rm -rf *)"
    ]
  }
}
```

- `allow` يقلل أسئلة الإذن للأوامر الآمنة المتكررة.
- `deny` يحمي الأسرار من القراءة أصلاً — أقوى من الاعتماد على الانتباه.
- `settings.local.json` للإعدادات الخاصة بجهازك، ويُضاف إلى `.gitignore`.
- في جلسات الجوال والويب قد لا تُطبَّق كل الإعدادات؛ لا تجعل الأمان معتمداً عليها وحدها.

## MCP داخل المستودع `.mcp.json`

لربط خدمات خارجية (قاعدة بيانات، أدوات) بالجلسة:

```json
{
  "mcpServers": {
    "supabase": { "type": "http", "url": "https://..." }
  }
}
```

لا تضع رموز الوصول داخل هذا الملف — استخدم متغيرات بيئة أو أسرار المستودع.

```
│   ├── SPEC.md                ← المواصفة وخطة المراحل

```

## الصيانة

- راجع `CLAUDE.md` شهرياً واحذف ما لم يعد صحيحاً — التعليمات القديمة أسوأ من غيابها.
- إن تكرر تجاهل قاعدة، فغالباً هي مدفونة في ملف طويل: اختصر ورفّع القاعدة لأعلى.
- إن كان لديك مهارات كثيرة، تأكد أن أوصافها **متمايزة**؛ الأوصاف المتشابهة تُربك الاختيار.
- حدّث `PROJECT_STATUS.md` في نهاية كل جلسة كبيرة حتى تبدأ الجلسة التالية من حيث انتهيت.
