# تحسين محركات البحث للمواقع

مسار الويب — ليس Flutter. الترتيب حصيلة ثلاثة أشياء بهذا الترتيب: **صفحة يمكن الوصول إليها وفهرستها**، **محتوى يجيب على نية البحث**، **تجربة لا تطرد الزائر**. البقية تفاصيل.

## الزحف والفهرسة أولاً

قبل أي تحسين، تأكد أن الصفحة: (1) لها عنوان URL ثابت، (2) مرتبطة من داخل الموقع، (3) تعيد `200`، (4) غير محجوبة، (5) محتواها موجود في HTML الذي يستقبله الزاحف.

| المانع | كيف تكتشفه |
|---|---|
| `noindex` منسي من بيئة التجربة | ابحث عن `<meta name="robots">` في الإنتاج |
| `Disallow` في robots.txt | افتح `/robots.txt` واقرأه |
| صفحة يتيمة بلا روابط داخلية | زحف داخلي أو خريطة روابط |
| محتوى يظهر بعد JS فقط | اعرض الصفحة بلا JS وانظر ما يبقى |
| سلسلة إعادة توجيه أو `404` ناعم | فحص حالة الاستجابة |

`robots.txt` يمنع **الزحف** لا الفهرسة: صفحة محجوبة قد تظهر في النتائج بلا وصف. لمنع الظهور استعمل `noindex` واترك الصفحة قابلة للزحف حتى يقرأه الزاحف.

## العنوان والوصف

| العنصر | الطول العملي | القاعدة |
|---|---|---|
| `<title>` | 50–60 حرفاً لاتينياً (30–35 كلمة عربية أقصر) | الكلمة الأهم أولاً، ثم اسم الموقع |
| `<meta name="description">` | 120–155 حرفاً | ملخص يقنع بالضغط، ليس عامل ترتيب مباشر لكنه يرفع نسبة النقر |

```html
<title>قطع غيار السيارات في طرابلس — متجر النور</title>
<meta name="description" content="فلاتر وبطاريات وزيوت أصلية بأسعار محدّثة، توصيل داخل طرابلس والدفع عند الاستلام.">
```

- عنوان فريد لكل صفحة. عناوين متكررة = صفحات تتنافس مع بعضها.
- لا حشو كلمات مفتاحية؛ يخفض النقر ولا يرفع الترتيب.
- النص العربي أعرض بصرياً في نتائج البحث؛ اجعل الرسالة كاملة في أول 40 حرفاً.
- محرك البحث قد يعيد كتابة الوصف؛ العنوان الجيد أهم من الوصف الجيد.

## بنية العناوين والروابط الداخلية

- `h1` واحد يطابق موضوع الصفحة، وبقية العناوين بترتيب هرمي بلا قفز.
- نص الرابط يصف الوجهة: "دليل الشحن إلى بنغازي" لا "اضغط هنا". نص الرابط أقوى إشارة تعطيها لصفحة أخرى.
- كل صفحة مهمة على بُعد **≤ 3 نقرات** من الصفحة الرئيسية.
- اربط الصفحات المرتبطة موضوعياً ببعضها (عنقود محتوى حول صفحة محورية).
- فتات الخبز (breadcrumbs) تحسّن الفهم والعرض في النتائج.
- بنية URL: قصيرة، بشرطات، بلا معاملات لا لزوم لها، حروف صغيرة، ثابتة. العربية في الرابط تعمل لكنها تُرمَّز عند النسخ؛ الترجمة الصوتية اللاتينية أسهل للمشاركة.

## sitemap.xml وrobots.txt

```
# /robots.txt
User-agent: *
Allow: /
Disallow: /admin/
Disallow: /*?session=
Sitemap: https://example.ly/sitemap.xml
```

كل مدخل في `sitemap.xml` هو `<url>` يحتوي `<loc>` (رابط مطلق) و`<lastmod>` بصيغة `YYYY-MM-DD`.

- خريطة الموقع تحتوي الصفحات **القابلة للفهرسة فقط**: بلا `noindex`، بلا إعادة توجيه، بلا نسخ غير أساسية.
- الحد: 50,000 رابط أو 50MB غير مضغوط لكل ملف؛ استعمل فهرس خرائط عند التجاوز.
- `lastmod` يجب أن يكون صادقاً؛ تحديثه بلا تغيير حقيقي يُهمَل.
- لا تحجب ملفات CSS وJS في robots.txt — الزاحف يحتاجها لعرض الصفحة والحكم عليها.

## البيانات المنظّمة JSON-LD

تُضاف في `<script type="application/ld+json">` وتفتح عروضاً غنية في النتائج. استعمل الأنواع المطابقة لمحتواك فعلاً.

```html
<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@type": "Product",
  "name": "فلتر زيت أصلي",
  "image": ["https://example.ly/img/filter.jpg"],
  "brand": { "@type": "Brand", "name": "Bosch" },
  "offers": {
    "@type": "Offer",
    "price": "45.00",
    "priceCurrency": "LYD",
    "availability": "https://schema.org/InStock",
    "url": "https://example.ly/products/oil-filter"
  }
}
</script>
```

الأنواع الأكثر فائدة: `Organization` و`LocalBusiness` (مع العنوان وساعات العمل للنشاط المحلي)، `Product` + `Offer`، `Article`/`BlogPosting`، `FAQPage`، `BreadcrumbList`، `Event`.

قواعد: البيانات المنظّمة يجب أن **تطابق ما يراه المستخدم** على الصفحة — تقييمات أو أسعار غير ظاهرة تعرّض الموقع لعقوبة يدوية. لا تضف `FAQPage` لأسئلة غير موجودة نصياً. تحقّق دائماً بأداة اختبار النتائج الغنية قبل النشر.

## canonical

```html
<link rel="canonical" href="https://example.ly/products/oil-filter">
```

- كل صفحة تحمل canonical، حتى لو أشارت لنفسها — يحمي من نسخ ناتجة عن معاملات (`?utm_source=`, `?sort=`).
- النسخ المكرّرة (صفحة قابلة للطباعة، نفس المنتج في تصنيفين) تشير كلها للنسخة الأساسية.
- الرابط **مطلق** ويطابق النسخة المفضّلة تماماً: نفس البروتوكول، ووجود/غياب `www`، ووجود/غياب الشرطة الأخيرة.
- canonical إشارة قوية لا أمر؛ ادعمها بروابط داخلية تشير للنسخة نفسها.
- الترقيم (pagination): كل صفحة canonical لنفسها، لا للصفحة الأولى.

## hreflang للمواقع العربية/الإنجليزية

عند وجود نسختين لغويتين لنفس المحتوى، تُبلغ hreflang محرك البحث أيها يعرض لمن. كل صفحة تسرد **كل** النسخ بما فيها نفسها، والإشارات متبادلة وإلا تُتجاهل.

```html
<link rel="alternate" hreflang="ar" href="https://example.ly/ar/shipping">
<link rel="alternate" hreflang="en" href="https://example.ly/en/shipping">
<link rel="alternate" hreflang="x-default" href="https://example.ly/ar/shipping">
```

- الرمز لغة (`ar`) أو لغة-بلد (`ar-LY`, `ar-EG`). استعمل اللغة وحدها إلا إذا كان المحتوى مختلفاً فعلاً بين البلدان (عملة، أسعار، شحن).
- `x-default` للصفحة التي تُعرض عند عدم التطابق.
- الروابط مطلقة، وكل نسخة تعيد `200` لا إعادة توجيه.
- لا تخلط hreflang مع canonical متعارض: canonical كل صفحة يشير لنفسها، لا للنسخة الأخرى.
- الترجمة الآلية الرديئة أسوأ من عدم الترجمة: صفحة عربية ضعيفة لن ترتّب، وقد تُصنّف محتوى منخفض القيمة.

## السرعة وتجربة الصفحة كعامل ترتيب

- Core Web Vitals عامل ترتيب حقيقي لكنه **مرجّح ضعيف** مقارنة بجودة المحتوى ومطابقة النية. لا تتوقع قفزة من تحسين LCP وحده على محتوى ضعيف.
- أثره الأكبر ككاسر تعادل بين صفحات متقاربة الجودة، وفي معدل الارتداد الفعلي.
- الأهداف: LCP ≤ 2.5s، INP ≤ 200ms، CLS ≤ 0.1 عند الشريحة 75.
- التوافق مع الجوال شرط لا تحسين: الفهرسة تعتمد نسخة الجوال أساساً.
- HTTPS إلزامي، والإعلانات المتطفّلة تضرّ.

> تفاصيل تحسين هذه المؤشرات: افتح web-performance.

## قيود تطبيقات الصفحة الواحدة (SPA)

هذه أهم نقطة تقنية لموقع React أو Vue.

- محركات البحث الكبرى تنفّذ JavaScript، لكن ذلك يمرّ بمرحلة عرض مؤجّلة قد تتأخر من ساعات إلى أيام، وقد تُقطع عند حد زمني أو عند فشل سكربت واحد.
- المحرّكات الأصغر وروبوتات المعاينة الاجتماعية (واتساب، تويتر، فيسبوك، تيليجرام) **لا تنفّذ JS إطلاقاً**: بلا HTML من الخادم لن تظهر أي معاينة عند مشاركة الرابط — وهذا مهم عملياً في السوق العربي حيث التوزيع عبر واتساب.
- الأعراض المعتادة: كل الصفحات تحمل نفس `<title>` والوصف، لأن العميل يغيّرها بعد التحميل.

الحلول بترتيب المتانة:

| الحل | ملاحظة |
|---|---|
| توليد ثابت (SSG) لكل صفحة عامة | الأفضل للمحتوى الذي لا يتغيّر كل دقيقة |
| عرض من الخادم (SSR) | للمحتوى المتغيّر الذي يجب فهرسته |
| العرض المسبق للروبوتات فقط | حل ترقيعي، وخطر التقديم المتباين إن اختلف المحتوى |
| SPA خالص | مقبول فقط لما هو خلف تسجيل الدخول |

قواعد إضافية للـ SPA: التنقّل بروابط `<a href>` حقيقية لا `onClick` مع `pushState` فقط؛ كل مسار له عنوان فعلي يعمل عند التحديث المباشر؛ حدّث `title` و`description` وOpen Graph لكل مسار على الخادم لا على العميل فقط؛ الصفحة غير الموجودة تعيد `404` حقيقياً لا `200` بصفحة فارغة.

## محتوى يستحق الترتيب

- ابدأ من **نية البحث** لا من الكلمة: هل الباحث يريد تعريفاً، مقارنة، أم الشراء الآن؟ الصفحة تطابق النية أو لا ترتّب مهما حُسّنت تقنياً.
- صفحة واحدة شاملة لكل موضوع؛ خمس صفحات ضعيفة عن نفس الموضوع تتنافس فيما بينها وتخسر كلها (تنافس داخلي).
- أجب عن السؤال في أول 100 كلمة، ثم فصّل.
- خبرة أصلية: أسعار حقيقية، صور خاصة، بيانات محلية. المحتوى المولّد آلياً بلا قيمة مضافة لا يرتّب.
- حدّث الصفحات المهمة دورياً؛ الأسعار والأرقام القديمة تخفض الثقة.
- للسوق المحلي: أنشئ ملف نشاط تجاري، واذكر المدينة والخدمات صراحة، وأضف `LocalBusiness` منظّم — البحث المحلي أسرع مسار لنتائج فعلية.

## أخطاء شائعة

- `noindex` أو `Disallow: /` منقول من بيئة التجربة إلى الإنتاج.
- SPA بلا عرض خادم، ثم استغراب غياب المعاينة في واتساب وغياب الصفحات من الفهرس.
- عنوان ووصف موحّدان لكل الصفحات.
- canonical يشير لصفحة أخرى بالخطأ فتختفي الصفحة من النتائج.
- hreflang من طرف واحد بلا إشارة متبادلة.
- بيانات منظّمة لتقييمات أو أسعار غير ظاهرة على الصفحة.
- ملاحقة الكلمات المفتاحية بدل نية البحث.
- حجب CSS/JS في robots.txt.
- ترجمة آلية للنسخة العربية بلا مراجعة.

## قائمة تحقق

- [ ] لا `noindex` ولا `Disallow` غير مقصود في الإنتاج، وCSS/JS غير محجوبة
- [ ] كل صفحة مهمة على بُعد ≤ 3 نقرات وليست يتيمة
- [ ] عنوان ووصف فريدان لكل صفحة، وبالطول المناسب
- [ ] `h1` واحد وبنية عناوين بلا قفز، ونصوص روابط وصفية
- [ ] `sitemap.xml` يحتوي الصفحات القابلة للفهرسة فقط ومذكور في robots.txt
- [ ] canonical مطلق على كل صفحة ومتسق مع الروابط الداخلية
- [ ] hreflang متبادل بين النسختين مع `x-default`
- [ ] JSON-LD مطابق للمحتوى الظاهر ومُختبَر بأداة النتائج الغنية
- [ ] المحتوى المطلوب فهرسته موجود في HTML القادم من الخادم
- [ ] التنقّل بروابط `<a href>` حقيقية، وكل مسار يعمل عند التحديث المباشر، والمفقود يعيد 404
- [ ] Open Graph مضبوطة لكل صفحة واختُبرت المعاينة في واتساب
- [ ] الصفحة تطابق نية بحث واحدة، ولا تنافس داخلي بين صفحات
- [ ] Core Web Vitals ضمن العتبات والموقع متوافق مع الجوال وعلى HTTPS
