# دفعُ المشروع إلى مستودعك — من هاتفك

## لماذا لم أدفعه أنا

حاولتُ، وسُدَّ الطريقان:

```
GitHub API   → 403  "GitHub access to this repository is not enabled for this session"
git push     → "Invalid username or token"
```

الرمزُ المتاح لي في هذه الجلسة **مقصورٌ على مستودعاتٍ مُلحَقةٍ بها مسبقًا**،
ومستودعُك ليس منها. وهذا ليس عطبًا في الشيفرة ولا في مستودعك — قيدُ بيئةٍ.
ولن أدّعيَ أنني دفعتُه وأنا لم أفعل.

**وأمامك طريقان: الأوّل أسرع إن أتاحه تطبيقُك، والثاني يعمل قطعًا.**

---

## الطريقُ الأوّل: تُلحِق المستودعَ بالجلسة

رسالةُ الخطأ نفسُها تقول: `Use add_repo to request access`. فإن وجدتَ في
تطبيق Claude خيارًا لإضافة مستودع GitHub أو منح صلاحيّةٍ عليه، فعّله على
`daood40/FALAH-Flutter-app-Android-iOS-` ثم قل لي «أُلحق» — وأدفعه في دقيقة.

وإن لم تجد الخيار، فالطريقُ الثاني.

---

## الطريقُ الثاني: Termux — يعمل قطعًا

وأنت محتاجٌ إلى Termux على كلِّ حالٍ لتوليد مفتاح الرفع، فلا تخسر شيئًا.

### ١ · ثبّت Termux

من **F-Droid** لا من متجر Play (نسخةُ Play قديمةٌ ومهجورة):
<https://f-droid.org/packages/com.termux/>

### ٢ · جهّزه

```bash
pkg update && pkg upgrade -y
pkg install git -y
termux-setup-storage        # يطلب إذنَ الوصول إلى التخزين — اقبله
```

### ٣ · انقل الحزمة

نزّل `falah.bundle` من هذه المحادثة (٢٫٩ م.ب)، ثم:

```bash
cd ~
cp /sdcard/Download/falah.bundle .
ls -lh falah.bundle          # تأكّد أنها وصلت
```

### ٤ · فُكَّها — وفيها التاريخُ كلُّه

```bash
git clone falah.bundle FALAH
cd FALAH
git log --oneline | head -5
```

يجب أن ترى **٣٣ التزامًا و٢٩٧ ملفًّا**، والفرعُ `main` جاهزًا (لا يلزم
`git branch -M`). الحزمةُ ليست نسخةً مسطَّحةً من الملفّات
— هي المستودعُ بتاريخه كاملًا.

### ٥ · اربطه بمستودعك وادفعه

**انسخ الرابطَ من زرِّ `Code` الأخضر في صفحة مستودعك** — لا تكتبه يدويًّا،
فالاسمُ فيه شرطاتٌ ونقطةٌ يسهل الخطأُ فيها:

```bash
git remote remove origin
git remote add origin https://github.com/daood40/<الاسم-كما-نسختَه>.git
git push -u origin main
```

سيسألك عن اسم المستخدم وكلمة المرور:

- **Username:** `daood40`
- **Password:** ⚠ **ليست كلمةَ مرور حسابك** — GitHub لم يعد يقبلها.
  تحتاج **Personal Access Token**.

### ٦ · رمزُ الدخول (مرّةً واحدة)

من الهاتف: `github.com` ← صورتُك ← **Settings** ← **Developer settings** ←
**Personal access tokens** ← **Tokens (classic)** ← **Generate new token**

- **Note:** `termux-falah`
- **Expiration:** ٩٠ يومًا
- **Scopes:** ✅ **`repo` وحدَه** — لا تعطِه أكثر ممّا يلزم

انسخ الرمزَ فورًا (لن يظهر ثانيةً)، والصقه مكانَ كلمة المرور.

> ولئلّا يسألك في كلِّ مرّة:
> ```bash
> git config --global credential.helper store
> ```
> يحفظه في `~/.git-credentials` على هاتفك بنصٍّ صريح. مقبولٌ لجهازك، ولا
> تفعله على جهازٍ يشاركك فيه أحد.

## بعد الدفع — وما تتوقّعه بالضبط

افتح تبويب **Actions**. وسأقول لك ما ستراه قبل أن تراه، لئلّا تظنّ عطبًا
ما ليس بعطب:

| الوظيفة | أوّلُ تشغيلة | لماذا |
|---|---|---|
| `static` | ✅ أخضر | لا يحتاج شيئًا خارجيًّا |
| `flutter` | ✅ أخضر **ويُخرج APK** | الحزمةُ تُبنى أوّلًا، والاختباراتُ الحيّة تعمل بلا محتوى |
| `tests` | ❌ **أحمر — متوقَّع** | يحتاج قاعدةَ المحتوى |
| `build` | ⏭ يُتخطّى | مشروطٌ بنجاح `tests` |
| `QUALITY_GATE` | ❌ أحمر | لأنّ `tests` سقطت |

### لماذا `tests` أحمر — وهو ليس عيبًا

قاعدةُ المحتوى `falah.db` تُبنى من `raw/` وهو **١٦٥ ميغابايت**، ولا يدخل
git (والأنبوبُ نفسُه يرفض أيَّ ملفٍّ فوق ٢ م.ب). فالاستنساخُ النظيفُ لا
يملك النصوصَ الشرعيّة، ووظيفةُ `tests` تقول ذلك برسالةٍ صريحة:

```
::error::مجلّد raw/ غير موجود ولا قاعدةٌ محفوظة.
```

**ولم أجعلها تمرّ بالتحايل.** اختبارٌ لا يجري لا يُعلَن ناجحًا.

وحين تريد إخضارها: احفظ `falah.db` مرّةً في ذاكرة الأنبوب المؤقّتة، أو
أتِح `raw/` من تخزينٍ خارجيّ. وهي خطوةٌ تحتاج حاسوبًا، فأخّرها.

### وماذا عن وظيفة `flutter`؟

تعمل كاملةً: تُبنى الحزمةُ وتُفحص وتُرفع **قبل** أيِّ شيءٍ يمسّ الخادم. ثم
يقلع خادمُ مصادقةٍ بلا محتوى (بإعلانٍ صريح `FALAH_ALLOW_NO_CONTENT=1`)
فتجري ٥٦ اختبارًا حقيقيًّا. و١٣ اختبارًا يمسّ النصَّ الشرعيَّ **يُعلن
تخطّيه بالاسم** في السجلّ:

```
::warning::13 اختبارًا لم يجرِ بسببٍ معلَن — **غيرُ محقَّقةٍ لا ناجحة**
```

وأيُّ تخطٍّ **صامتٍ** يُسقط الأنبوب. الفرقُ بين «لم يجرِ لسببٍ نقوله»
و«لم يجرِ ولا ندري» هو الفرقُ بين تقريرٍ صادقٍ وخضرةٍ كاذبة.

انزل إلى **Artifacts** أسفل صفحة التشغيلة وستجد:

**`falah-android-staging-apk`** ← نزّله، فُكَّ الـzip، وثبّت الـAPK على
هاتفك. **هذا أوّلُ تشغيلٍ حقيقيٍّ للتطبيق على جهازك.**

> و`falah-android-production-aab` لن يظهر بعد — يحتاج أسرارَ التوقيع.
> راجع [`RELEASE_SIGNING.md`](RELEASE_SIGNING.md).

## ⚠ عن اسم المستودع المنتهي بـ `-.`

سألتَ إن كان يسبّب مشكلة. **الجوابُ الصادق: لا أستطيع التحقّق، وفيه خطرٌ
معروف.**

**لا أستطيع التحقّق** لأنّ واجهةَ GitHub محجوبةٌ عن هذه الجلسة (٤٠٣ حتى
بلا رمز)، فلم أقرأ اسمَ مستودعك الفعليّ.

**وأمّا الخطر:** وثائقُ GitHub تنصّ على أنّ الاسم يقبل `.` و`-` و`_`، ولا
تذكر شيئًا عن نقطةٍ في آخره — لا إجازةً ولا منعًا. لكنّ **تقاريرَ أعطابٍ
مفتوحةً في libgit2 وGitLab** تُظهر أنّ اسمًا ينتهي بنقطةٍ يكسر الاستنساخَ
في بعض العملاء، ويستحيل على Windows أصلًا (لا يقبل مسارًا ينتهي بنقطة).

فالتوصية: **أعِد تسميته إلى `FALAH-Flutter-app-Android-iOS`** (بلا `-.`)
من `Settings ← Repository name`. وGitHub يُبقي إعادةَ توجيهٍ من الاسم
القديم، فلا يضيع شيء. وهي خطوةُ ثوانٍ الآن، وصداعٌ لاحقًا.

وعلى كلٍّ: **انسخ الرابطَ من زرِّ `Code` الأخضر** ولا تكتبه — فما تنسخه هو
الصحيح أيًّا كان الاسم.

## ⚠ قبل أن تجعل المستودعَ عامًّا

**اجعله خاصًّا (Private) الآن.** وقبل أيِّ فتحٍ للعموم:

1. احسم رخصةَ التفسير الميسّر (§٤ في `LAUNCH_CHECKLIST.md`).
2. تأكّد أنّ `deploy/.env` ليس فيه — `git ls-files | grep .env` يجب أن
   يعيد `deploy/.env.example` **فقط**.
3. أضف ملفَّ رخصةٍ للشيفرة نفسِها.
