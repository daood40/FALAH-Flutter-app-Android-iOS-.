# P1.2 — تصميمُ الهوية والصلاحيات وسجلّ التدقيق

> **هذه وثيقةُ تصميمٍ تسبق الشيفرة.** كُتبت قبل كتابة سطرٍ من P1.2، وما
> يخالفها في التنفيذ يُذكر في التقرير النهائيّ صراحةً.

القاعدةُ الحاكمة، وهي التي يُحتكم إليها عند كل اختلاف:

```
UNKNOWN                    = DENY
MISSING POLICY             = DENY
MISSING IDENTITY           = DENY
MISSING RESOURCE OWNERSHIP = DENY
AUTH FAILURE               = DENY
LOOKUP FAILURE             = DENY      ← fail closed
```

---

# ١ · القرار المعماريّ الأساس

طبقةُ P1.1 تقرّر بـ`can(subject, action, resource)`، وشرطُها اليوم دالّةٌ
واحدة (`OWNER` · `SELF` · `NEEDS(perm)` …). P1.2 **لا يستبدل هذا**، بل
يشقّ الشرطَ الواحد إلى **بوّابتين مستقلّتين يجب أن تُفتحا معًا**:

```
can(subject, action, resource)
        │
        ├── ① بوّابةُ الصلاحية:  هل يملك دورُ الفاعل الصلاحيةَ "<مورِد>.<فعل>"؟
        │                        (سؤالٌ عن الفاعل — لا يعرف أيَّ مورِدٍ بعينه)
        │
        └── ② بوّابةُ النطاق:    وهل هذا المورِدُ **بعينه** في نطاقه؟
                                 OWNER · SELF · ANY · PUBLIC
```

**ولماذا اثنتان لا واحدة؟** لأن الخلطَ بينهما هو أصلُ فوضى
`if role == "admin"`. «يملك صلاحية تعديل مشروع» شيء، و«هذا المشروع له»
شيءٌ آخر. من خلطهما اضطُرّ أن يكتب استثناءَ الإداريّ في كل معالِج. ومن
فصلهما كتب: الإداريُّ يملك صلاحيةً أوسع، ونطاقُه `ANY` — سطرٌ واحدٌ في
جدول، لا شرطٌ في مئة دالّة.

**واسمُ الصلاحية هو الزوجُ نفسُه**: `project.update` هي بالضبط
`(resource="project", action="update")`. ولهذا فائدةٌ لا تُقدَّر: **لا
يمكن أن توجد عمليةٌ بلا صلاحية**، لأن الصلاحيةَ ليست شيئًا يُكتب إلى
جانب العملية بل هي اسمُها. والفحصُ الآليّ يثبت ذلك (§٩).

# ٢ · نموذج الهوية

## ٢٫١ · `users` — ما هو قائمٌ اليوم

| الحقل | النوع | ملاحظة |
|---|---|---|
| `id` | INTEGER PK | |
| `email` | TEXT UNIQUE NOT NULL | مطبَّعٌ إلى الحروف الصغيرة |
| `name` · `watermark` | TEXT | |
| `pw_hash` · `pw_salt` · `pw_iter` | BLOB · BLOB · INTEGER | PBKDF2-SHA256 · ٢٤٠٬٠٠٠ |
| `status` | TEXT DEFAULT `'active'` | `active` \| `suspended` |
| `verified_at` | INTEGER | وقتُ تأكيد البريد |
| `created_at` · `last_login` | INTEGER | |

## ٢٫٢ · ما يُضاف في P1.2

| الحقل | النوع | لماذا |
|---|---|---|
| **`role`** | `TEXT NOT NULL DEFAULT 'user'` | الدورُ الوحيد لكل حساب |
| **`role_changed_at`** | `INTEGER` | متى تغيّر آخرَ مرّة (للسجلّ والقراءة) |

**`updated_at` و`deleted_at` لا يُضافان.** الحذفُ في فلاح **صلبٌ
ونهائيّ** بقرارٍ سابق (`auth.delete_account`)، والحذفُ المنطقيّ بندٌ في
`P1.5` لم يُطلب الآن. وإضافةُ `deleted_at` بلا تنفيذٍ يستعمله عمودٌ يكذب.

`last_login` موجودٌ سلفًا ويكفي عن `last_login_at`.

**والافتراضيُّ `'user'` — أقلُّ صلاحيةٍ ممكنة.** ولا مستخدمَ قائمٌ يصير
إداريًّا بسبب هجرة (§٧).

## ٣٫٢ · صلاحياتُ الإدارة (٧ — جديدة)

| الصلاحية | النطاق | ماذا تفتح |
|---|---|---|
| `user.list` | ANY | سردُ الحسابات (بلا أسرارٍ ولا بريدٍ كامل — §٦٫٣) |
| `user.read` | ANY | قراءةُ حسابٍ بعينه |
| `user.update` | ANY* | إيقافُ حسابٍ وإعادةُ تفعيله |
| `role.read` | ANY | قراءةُ الأدوار وصلاحياتها |
| `role.assign` | ANY* | تغييرُ دورِ حساب |
| `audit.read` | ANY | قراءةُ سجلّ التدقيق |
| `billing.manage` | ANY | منحُ اشتراكٍ · قبولُ إيصالٍ موثوق |

`ANY*` يعني: النطاقُ عامّ **لكنّ حارسَ التسلسل يقيّده** — §٥.

**ولا `admin.*` ولا wildcard.** لا في الكتالوج ولا في التعيين. كلُّ
صلاحيةٍ مكتوبةٌ باسمها، و`authz_test.py` يثبت أنه لا نجمةَ في أيّ حزمة.

**ولا `system.manage`.** لم أجد عمليةً قائمةً تحتاجها اليوم، ولا أُنشئ
صلاحيةً لعمليةٍ لا وجود لها. تُضاف يوم تُضاف عمليتُها.

# ٤ · الأدوار

**الدورُ حزمةُ صلاحياتٍ، وليس شيئًا يُفحص باسمه.**
لا يُكتب في المشروع كلِّه `if role == "admin"` — و`authz_test.py` يفحص ذلك.

| الدور | صلاحياتُه |
|---|---|
| **`user`** | الـ٢٧ في §٣٫١ |
| **`moderator`** | `user` + `user.list` + `user.read` + `audit.read` |
| **`admin`** | `moderator` + `user.update` + `role.read` + `billing.manage` |
| **`super_admin`** | `admin` + `role.assign` |

التعيينُ **صريحٌ ومحسوبٌ بالضمّ** (`user ⊂ moderator ⊂ admin ⊂ super_admin`)
— ترتيبٌ خطّيّ لأن حالةَ الاستعمال اليوم خطّيّة. والبنيةُ لا تفترضه:
`ROLES` قاموسُ `اسم → مجموعةُ صلاحيات`، فدورٌ جانبيٌّ غيرُ خطّيّ يُضاف بلا
تغييرِ منطق.

**`super_admin` ليس تجاوزًا سحريًّا.** ما لا يتجاوزه، ولا سطرَ واحدًا:

- التحقّق من المدخل · `validate()` · حدودُ الأنواع
- CSRF · حدُّ حجم الطلب (٤١٣) · حدودُ الموارد
- حدُّ المعدّل
- **قيدُ الملكية على مواردِه هو**: مشروعُ غيره ليس مشروعَه. لا يقرأ
  `project.read` على مشروعٍ ليس له، لأن نطاقَ `project.read` هو `OWNER`
  لكلِّ دور. **ولا دورَ يوسّعه.**
- سجلُّ التدقيق: كلُّ فعلٍ له يُسجَّل كغيره
- **حارسُ التسلسل** (§٥)

هذا مقصود: الغرضُ من الإدارة أن تُدير الحسابات والأدوار والفوترة، لا أن
تقرأ محتوى الناس. ومن أراد ذلك غدًا يُنشئ له صلاحيةً باسمها ونطاقًا
`ANY` ويوثّقها ويختبرها — قرارٌ صريح، لا أثرٌ جانبيّ.

# ٥ · حارسُ التسلسل — منعُ تصعيد الامتياز

ثلاث قواعدَ في `authz` نفسها، لا في المعالِجات:

### ق١ — لا أحدَ يغيّر دورَ نفسه

```
actor.id == target.id  ⇒  DENY
```
تمنع `user → admin` وتمنع كذلك أن يُسقط آخرُ `super_admin` نفسَه فيقفل
النظام.

### ق٢ — لا تُمنح صلاحيةٌ لا تملكها

```
perms(الدور المطلوب) ⊄ perms(الفاعل)  ⇒  DENY
```
فـ`admin` لا يصنع `super_admin` (لأن `role.assign` ليست عنده)، ولا يصنع
دورًا يحمل صلاحيةً ينقصها.

### ق٣ — لا تُدار حسابٌ ليس دونك

```
perms(دور الهدف) ⊄ perms(الفاعل)  ⇒  DENY
```
فـ`admin` لا يوقف `admin` آخر ولا `super_admin`، و`moderator` لا يمسّ
أحدًا (لا `user.update` عنده أصلًا).

**والثلاثةُ تُطبَّق حتى على `super_admin`.** ق١ خصوصًا: لا استثناء.

### وما يُختبر صراحةً

```
user → moderator · user → admin · user → super_admin
moderator → admin · moderator → super_admin
admin → super_admin
admin → admin (تعديلُ نظير)
super_admin → نفسه
```
كلُّها `DENY`. وطرقُ المحاولة: حقلٌ في الجسم · إسنادٌ جماعيّ · مفاتيحُ
JSON مكرَّرة · حقولٌ غيرُ موثَّقة · مسارٌ بديل · تسابُق.

# ٦ · المصادقة — ما هو قائمٌ وما يتغيّر

## ٦٫١ · ما هو قائمٌ ويُبقى كما هو

مُراجَعٌ ضد بنود الأمر ٦ و٧ و٩، ويجتازها:

| البند | الحال |
|---|---|
| تجزئةُ كلمة المرور | **PBKDF2-SHA256 · ٢٤٠٬٠٠٠ دورة · ملحٌ ١٦ بايت لكل حساب** — خوارزميةُ كلماتِ مرورٍ مخصّصة، لا `sha256(pw)` ولا MD5 ولا نصٌّ ظاهر. من المكتبة القياسية، لا تعميةَ مخترَعة |
| المقارنة | `hmac.compare_digest` — زمنٌ ثابت |
| عددُ الدورات | يُحفظ مع كل حساب، فيُرفع مستقبلًا بلا كسرِ ما مضى |
| الجلسة | رمزٌ عشوائيّ ٣٢ بايت · **يُخزَّن مجزَّأً** · انتهاءٌ · حذفٌ عند الانتهاء |
| الكعكة | HttpOnly · SameSite=Strict · Secure في الإنتاج · Path=/ · **ولا شيءَ في `localStorage`** |
| الإبطال | تغييرُ الكلمة واستعادتُها يحذفان **كلَّ** جلسات الحساب |
| CSRF | ترويسةٌ + `Origin` |
| رموزُ الاستعادة | مجزَّأة · مرّةً واحدة · ساعةٌ (استعادة) ويومان (تأكيد) |
| حدُّ المحاولات | ٨/ربع ساعة لكل بريد · ٥ استعادات/ساعة · ٢٠ تسجيل/ساعة لكل عنوان — **كلُّها في الخادم**، وخلف وكيلٍ تُقرأ `X-Forwarded-For` **الأخيرة** وبإعلانٍ صريح فقط |

**فلا حاجةَ إلى Bearer tokens ولا إلى تغيير آلية المصادقة.** النظامُ
ويبٌّ بكعكةٍ آمنة، وهي الآلية الأنسب لبنيته. وتغييرُها بلا موجِبٍ مخاطرةٌ
بلا مقابل.

## ٦٫٢ · ما يُضاف

| الإضافة | لماذا |
|---|---|
| **حدٌّ لكل عنوان على الدخول** | اليوم الحدُّ لكل **بريد** (٨/ربع ساعة). فمن يجرّب ألفَ بريدٍ بكلمةٍ واحدة (password spraying) لا يبلغ الحدَّ أبدًا. يُضاف حدٌّ ثانٍ لكل عنوان **إلى جانبه** لا بدلًا منه |
| **تسجيلُ الدخول والخروج في سجلّ التدقيق** | `login.success` · `login.failure` · `logout` بعنوانٍ ووكيلٍ ونتيجة |

## ٦٫٣ · تعدادُ الحسابات — قرارٌ يُذكر لا يُغيَّر صمتًا

| المسار | يكشف؟ | القرار |
|---|---|---|
| `/app/login` | **لا** | الردُّ واحدٌ للبريد المجهول وللكلمة الخاطئة، والاشتقاقُ يُحسب في الحالين فلا يفرّق الزمن. **يبقى** |
| `/app/password/forgot` | **لا** | الردُّ واحدٌ سواءٌ وُجد أو لا. **يبقى** |
| `/app/verify/confirm` · `password/reset` | **لا** | «رمزٌ منتهٍ أو مستعمَل» في كل الحالات |
| **`/app/register`** | **نعم** | «هذا البريد مسجَّل من قبل» |

**قرارُ التسجيل: يبقى كما هو في P1.2، ولا يُغيَّر صمتًا.** والسبب:

1. تغييرُه يغيّر **جسمَ الردّ ورمزَه** على مسارٍ عامّ — أي كسرُ عقدٍ،
   والأمرُ يقول: أيُّ breaking change غير مخطَّط ⇒ **STOP**.
2. البديلُ الصحيح (قبولٌ صامتٌ + رسالةُ بريدٍ تقول «لك حسابٌ بالفعل»)
   **يحتاج SMTP مُتحقَّقًا منه**، وهو `UNVERIFIED` في خطّ الأساس. فبناؤه
   على قناةٍ لم تُجرَّب يستبدل تسريبًا صغيرًا بحسابٍ لا يُنشأ.
3. الحدُّ قائمٌ فعلًا: **٢٠ تسجيلًا في الساعة لكل عنوان**، فالتعدادُ
   الواسع محدود.

**وهذا بندُ قرارٍ لك**، مرفوعٌ في التقرير النهائيّ وفي `P1_BACKLOG.md`.
إن قلتَ «غيّره» غُيِّر في مرحلةٍ مرقَّمةٍ مع تحديثِ العقد.

# ٧ · قاعدة البيانات — الهجرة `005`

**إضافيّةٌ آمنةٌ بالتصنيف.** لا `DROP TABLE` ولا `DROP COLUMN` ولا نقلَ
بيانات ولا إعادةَ بناءِ جدول.

```sql
ALTER TABLE users ADD COLUMN role TEXT NOT NULL DEFAULT 'user';
ALTER TABLE users ADD COLUMN role_changed_at INTEGER;
CREATE INDEX ix_users_role ON users(role);

CREATE TABLE audit_logs(...);            -- §٨
CREATE INDEX ix_audit_at    ON audit_logs(at DESC);
CREATE INDEX ix_audit_actor ON audit_logs(actor_id, at DESC);
CREATE INDEX ix_audit_action ON audit_logs(action, at DESC);
CREATE TRIGGER audit_logs_no_update ...  -- append-only
CREATE TRIGGER audit_logs_no_delete ...
```

## البيانات القائمة

| السؤال | الجواب |
|---|---|
| هل تُفترض القاعدةُ فارغة؟ | **لا.** الهجرةُ تُجرَّب على قاعدةٍ **جديدة** وعلى **نسخةٍ من الحقيقية** |
| ماذا يصير دورُ من هو مسجَّلٌ اليوم؟ | **`'user'`** — أقلُّ صلاحية. الافتراضيُّ في العمود نفسه |
| هل يصير أحدٌ إداريًّا بالهجرة؟ | **لا. ولا واحد.** ويُختبر بعدَّ `role<>'user'` بعد الهجرة على نسخةٍ حقيقية = **صفر** |
| الملكيةُ القائمة | لا تُمَسّ: `projects.user_id` كما هي، ونطاقُ `OWNER` كما كان |
| الاسترجاع | العمودُ يبقى ولا يضرّ. الرجوعُ بالشيفرة وحدها |

## أوّلُ `super_admin` — كيف يُنشأ

**ليس عبر الشبكة، ولا بمفتاحٍ في ترويسة.** أمرٌ محلّيٌّ يُشغَّل على
الخادم من يملك القرصَ أصلًا:

```
python3 -m falah.roles grant <البريد> super_admin --reason "..."
```

- يفشل إن لم يوجد الحساب.
- **يُسجَّل في `audit_logs`** بفاعلٍ `system:cli` وسببٍ مكتوب.
- لا يعمل عبر HTTP بأي حال.

هذا هو البديلُ عن المفتاح المشترك: من يملك الخادمَ يملكه أصلًا، والفرقُ
أن الفعلَ **يترك أثرًا باسمه** بدل مفتاحٍ لا يقول مَن استعمله.

# ٨ · سجلّ التدقيق

## ٨٫١ · الجدول

| الحقل | ملاحظة |
|---|---|
| `id` | INTEGER PK |
| `at` | ثوانٍ |
| `request_id` | يربط ما جرى في طلبٍ واحد — §٨٫٤ |
| `actor_id` | **بلا FK** — السجلُّ يبقى بعد حذف الحساب |
| `actor_role` | الدورُ **لحظةَ الفعل**، لا الآن |
| `action` | من الكتالوج المغلق §٨٫٢ |
| `resource_type` · `resource_id` | على ماذا |
| `result` | `success` \| `failure` \| `denied` |
| `ip` · `user_agent` | مقطوعان بحدٍّ |
| `metadata` | JSON — **مصفًّى** §٨٫٣ |

## ٨٫٢ · كتالوجُ الأحداث — مغلق

**لا يُسجَّل كلُّ شيءٍ عشوائيًّا.** حدثٌ ليس في القائمة يرفع خطأً في
التطوير، فلا ينمو السجلُّ بلا حساب.

```
login.success · login.failure · logout
account.created · account.updated · account.deleted
password.changed · password.reset
role.changed
user.suspended · user.reactivated
subscription.granted · subscription.canceled · subscription.store_event
project.created · project.deleted
export.created · export.failed · export.completed
security.denied            ← كلُّ منعٍ من طبقة الإذن
audit.read
```

**`security.denied` خصوصًا**: كلُّ قرارِ منعٍ يُسجَّل بسببه (`not_found` ·
`forbidden` · `no_policy` · `unauthenticated`) — وهو ما يُظهر المسحَ
بالأرقام المتسلسلة قبل أن يجد شيئًا.

## ٨٫٣ · ما لا يُسجَّل — أبدًا

```
كلمةُ مرور · اشتقاقُها · ملحُها
رمزُ جلسةٍ أو تجزئتُه · كعكة
رمزُ استعادةٍ أو تأكيد
ترويسة Authorization · أيُّ مفتاح
حمولةُ إيصالِ متجرٍ خام
```

وليس هذا وعدًا في وثيقة: **مصفاةٌ في الشيفرة** تُسقط كل مفتاحٍ يطابق
نمطًا محظورًا من `metadata`، و**اختبارٌ** يُنشئ الأحداثَ كلَّها ثم يفتّش
الجدول كلَّه عن آثارِ سرٍّ معروفٍ سلفًا.

## ٨٫٤ · `request_id` — الحدُّ الأدنى فقط

معرّفٌ عشوائيّ قصير يُولَّد **مرّةً لكل طلب** ويُحمَل في `Request`
ويُكتب في كل سطرِ تدقيقٍ من ذلك الطلب.

**ولا يُبنى عليه شيءٌ من P1.3**: لا سجلٌّ مهيكل، ولا مقاييس، ولا تتبّعٌ
موزَّع، ولا ترويسةُ ردٍّ جديدة (فذلك تغييرُ عقد). هذا هو الحدُّ الأدنى
الذي يحتاجه التدقيقُ ولا أكثر.

## ٨٫٥ · المنعة من العبث

| الطبقة | الآلية |
|---|---|
| القاعدة | **مُشغِّلان (triggers)**: `UPDATE` و`DELETE` على `audit_logs` يُجهضان بـ`RAISE(ABORT)` |
| التطبيق | لا مسارَ يكتب إلا `audit.record`، ولا مسارَ يعدّل أو يحذف — لا للمستخدم ولا للإداريّ ولا لـ`super_admin` |
| حذفُ الحساب | `delete_account` لا يمسّ `audit_logs` (لا عمودَ `user_id` فيه، وليس في قائمة جداوله) |
| التصحيح | **حدثٌ جديد**، لا تعديلُ القديم |
| القراءة | `audit.read` وحدها |

**وحدُّ هذه المنعة يُقال صراحةً:** من يملك ملفَّ `app.db` على القرص يملك
أن يُسقط المُشغِّل ويكتب ما شاء. الحمايةُ هنا **من التطبيق ومن مستعمليه**،
لا من مالك الخادم. حمايةُ الأخير تحتاج سلسلةَ تجزئةٍ أو سجلًّا خارج
الجهاز — **بندُ دفترٍ مؤجَّل، لا وعدٌ هنا**.

# ٩ · تغطيةُ الإذن الآلية

فحصٌ يجري في `make gate`، غرضُه أن يبقى النظامُ آمنًا **بعد ستة أشهر
ومطوّرٍ جديد**:

| ما يُثبَت | كيف يسقط |
|---|---|
| كلُّ مسارٍ في الجدول له `(resource, action)` | مسارٌ بلا إعلان |
| ولكلِّ زوجٍ سياسةٌ في `POLICY` | مسارٌ جديد بلا سياسة |
| ولكلِّ زوجٍ **صلاحيةٌ باسمه** في `PERMISSIONS` | صلاحيةٌ منسيّة |
| وكلُّ صلاحيةٍ يملكها **دورٌ واحدٌ على الأقلّ** | صلاحيةٌ لا يبلغها أحد |
| ولا صلاحيةَ في دورٍ ليست في الكتالوج | خطأٌ مطبعيّ في التعيين |
| ولا نجمةَ (`*`) في أيّ حزمةِ صلاحيات | wildcard تسلّل |
| ولا اسمَ دورٍ مقارَنٌ في شيفرة التطبيق | `if role == "admin"` ظهر |
| ولا مسارَ يُقرَّر إذنُه باسمه | سلسلةُ مسارٍ في `POLICY` |

**المسارُ الجديد بلا إذنٍ = بوّابةٌ ساقطة، لا مراجعةٌ بشرية.**

# ١٠ · تغييراتُ العقد — مُعلَنةٌ سلفًا

| التغيير | النوع | لماذا |
|---|---|---|
| `/app/me` يضيف `role` | **إضافيّ** — لا يكسر عميلًا | ليعرف العميلُ ما يعرضه. **قراءةٌ فقط، ولا يُقبل من العميل أبدًا** |
| **`X-FALAH-ADMIN` يُلغى** | **كاسر** — مقصودٌ ومطلوب | «لا أريد Shared Key كبديل للحسابات». `/app/subscription/grant` صار يشترط `billing.manage` من دورٍ حقيقيّ |
| مساراتٌ إدارية جديدة | إضافيّ | `/app/admin/users` · `/app/admin/users/role` · `/app/admin/users/status` · `/app/admin/audit` |

**ولا شيءَ غير هذا.** بقيّةُ المسارات الـ٦٠ بردودها ورموزها وسلوك أخطائها
كما هي، والعقدُ يحرس ذلك.

### عن إلغاء المفتاح — بصراحة

هذا **كسرٌ تشغيليّ**: من كان يستعمل `X-FALAH-ADMIN` اليوم يتوقّف غدًا.
والمسارُ البديل مكتوبٌ في §٧: حسابٌ يُرقّى بأمرٍ محلّيّ إلى `super_admin`.
مذكورٌ هنا قبل التنفيذ، وفي التقرير بعده، وفي `API.md` بينهما — لا
مفاجأة.

# ١١ · ما لا يدخل P1.2

`P1.3` مراقبة · `P1.4` CSP/HSTS · `P1.5` حذفٌ منطقيّ · `P1.6` كنسٌ ·
`P1.7` واجهةُ إدارة · `P1.8` i18n · Postgres · إعادةُ تصميم · أيُّ
تفكيكٍ غير لازم.

المكتوبة.
