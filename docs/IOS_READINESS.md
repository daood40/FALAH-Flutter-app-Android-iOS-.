# iOS — ما جهّزناه، وما ينتظر جهازًا

**الحالة:**

```
IOS PROJECT = READY
IOS BUILD   = UNVERIFIED
السبب       = يحتاج macOS + Xcode + اعتمادات توقيعٍ من حساب Apple Developer
```

> ولا يُقال غيرُ ذلك: **لم يُبنَ أرشيفُ iOS ولم يُشغَّل التطبيقُ على جهاز
> iPhone قطّ.** وكلُّ ما دونه أُعدّ ويُقرأ في الفروق، لكنّ صحّتَه لا تُثبت
> إلا ببناءٍ فعليّ.

## ١ · ما أُعدّ فعلًا

| # | العنصر | قبل | بعد |
|---|---|---|---|
| ١ | **مُعرِّفُ الحزمة** | `com.falah.falahApp` | **`com.falah.app`** — مطابقٌ لأندرويد |
| ٢ | مُعرِّفُ الاختبارات | `com.falah.falahApp.RunnerTests` | `com.falah.app.RunnerTests` |
| ٣ | الاسمُ الظاهر | `Falah App` | **`فَلاح`** |
| ٤ | اسمُ الحزمة | `falah_app` | `فَلاح` |
| ٥ | لغةُ التطوير | `$(DEVELOPMENT_LANGUAGE)` | **`ar`** |
| ٦ | اللغاتُ المعلَنة | — | **`ar`, `en`** |
| ٧ | إعلانُ التعمية | — | **`ITSAppUsesNonExemptEncryption = false`** |
| ٨ | أمنُ النقل | افتراضيّ | **`NSAllowsArbitraryLoads = false`** |
| ٩ | الاتّجاهاتُ على الهاتف | ٣ (رأسيٌّ + أفقيّان) | **رأسيٌّ فقط** |
| ١٠ | شريطُ الحالة | — | `UIViewControllerBasedStatusBarAppearance` |

### ولماذا هذه بالذات

**(١) المعرِّف** — كان `com.falah.falahApp`: اسمُ مجلَّدٍ مولَّدٌ لا اسمُ
منتَج. والمعرِّفُ **لا يتغيّر بعد أوّل رفع**، فتصحيحُه الآن مجّانيّ وبعد
الرفع مستحيل. ومطابقتُه لأندرويد تجعل الروابطَ العميقةَ والدعمَ واحدًا.

**(٥) و(٦) اللغة** — التطبيقُ عربيٌّ من اليمين لليسار. و`ar` لغةً للتطوير
تجعل النظامَ يضبط اتّجاهَ الواجهة صحيحًا من أوّل إقلاع، لا بعد أن يقرأ
تفضيلاتِ المستخدم.

**(٧) إعلانُ التعمية** — App Store Connect يسأل عنه **في كلِّ رفعة**، وبدونه
يقف الرفعُ منتظرًا جوابًا. والقيمةُ `false` صحيحةٌ هنا: التطبيقُ يستعمل
HTTPS القياسيَّ وحدَه، وهو معفًى صراحةً من قيود التصدير.

**(٨) أمنُ النقل** — `false` تمنع أيَّ اتّصالٍ غيرِ مشفَّرٍ من التطبيق. وهو
الصحيح: الخادمُ على HTTPS، و`Env.assertValid()` في Dart يرمي عند الإقلاع
إن كان الوضعُ إنتاجًا والعنوانُ ليس `https`. **طبقتان لا واحدة.**

**(٩) الاتّجاه** — البطاقاتُ تُصمَّم مربّعةً أو طوليّة، والوضعُ الأفقيُّ على
الهاتف يكسر تخطيطَها. أمّا الآيباد فتُترك اتّجاهاتُه كما هي لأنّ Apple
تتوقّعها في المراجعة.

## ٢ · ما لا يمكن التحقّقُ منه هنا — ولماذا

| ما | لماذا يستحيل بلا Mac |
|---|---|
| `flutter build ios` | يحتاج Xcode وسلسلةَ أدواتِ Apple |
| `pod install` | CocoaPods يحتاج بيئةَ macOS |
| توقيعُ الأرشيف | يحتاج شهادةً وملفَّ تزويدٍ من حسابٍ حقيقيّ |
| الرفعُ إلى TestFlight | يحتاج أرشيفًا موقَّعًا |
| السلوكُ على جهازٍ فعليّ | يحتاج جهازًا |

**ولن نكتب `PASS` لواحدةٍ منها.**

## ٣ · ما ينقص ولا يحتاج Mac — لكنه يحتاج قرارَك

### الأيقونات

Flutter يضع أيقوناتٍ افتراضيّةً (شعارَ Flutter) في
`ios/Runner/Assets.xcassets/AppIcon.appiconset/`. **و Apple ترفض التطبيقَ
بأيقونةٍ افتراضيّة.**

والمشروعُ يملك أيقونةَ أندرويد في `icons/`. توليدُ مقاساتِ iOS منها لا يحتاج
Mac:

```bash
dart pub global activate flutter_launcher_icons
# ثم في pubspec.yaml:
#   flutter_launcher_icons:
#     ios: true
#     image_path: "assets/icon.png"   # ١٠٢٤×١٠٢٤ بلا شفافيّة
dart run flutter_launcher_icons
```

> **لم يُنفَّذ**: يحتاج أصلًا ١٠٢٤×١٠٢٤ معتمَدًا منك. واختيارُ هُويّةٍ بصريّةٍ
> قرارُ مالكٍ لا قرارُ مطوّر.

### شاشةُ الإقلاع

`LaunchScreen.storyboard` افتراضيّةٌ بيضاء. مقبولةٌ للمراجعة، ولا تشبه
التطبيق. تُحرَّر بمحرّر نصوصٍ (XML) أو في Xcode لاحقًا.

## ٤ · حين يتوفّر Mac — بالترتيب

```bash
cd falah_app
flutter clean && flutter pub get
cd ios && pod install && cd ..

# (١) بناءٌ بلا توقيع — يثبت أنّ الشيفرةَ تُترجم
flutter build ios --release --no-codesign

# (٢) ثم في Xcode: افتح ios/Runner.xcworkspace (لا .xcodeproj)
#     Signing & Capabilities ← اختر الفريق ← دع Xcode يُدير التزويد
#     Product ← Archive ← Distribute App ← App Store Connect
```

**والترتيبُ مقصود:** الخطوةُ (١) تفصل «هل تُترجم الشيفرة؟» عن «هل التوقيعُ
مضبوط؟». وخلطُهما يجعل كلَّ خطأٍ يبدو خطأَ توقيع.

### البديلُ إن لم يكن عندك Mac

خدماتُ البناء السحابيّة (Codemagic · Bitrise · GitHub Actions بعدّاءِ
`macos-latest`) تبني وتوقّع بلا أن تملك جهازًا. وكلُّها تحتاج **اعتمادات
Apple** منك، وتُعطَى مفاتيحَ API مقصورةً — لا كلمةَ مرورِ Apple ID.
