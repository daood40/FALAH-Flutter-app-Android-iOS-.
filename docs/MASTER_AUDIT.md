## ٢ · API CLIENT AUDIT

كل طبقة النداء هي هذه الدالة (السطور 272–279):

```js
async function api(path, body) {
  const o = body ? {method:"POST", headers:{"Content-Type":"application/json","X-FALAH":"1"},
                    body: JSON.stringify(body)} : {};
  const r = await fetch(path, o);
  let d = {}; try { d = await r.json(); } catch (e) {}
  if (!r.ok) throw new Error(d.error || ("خطأ " + r.status));
  return d;
}
```

### ٧٫٢ العيب: القشرة كما هي مُعدَّة **لا تستطيع المصادقة**

الشرط الوحيد لعمل القشرة هو أن يكون:

```
hostname في capacitor.config  ==  FALAH_API في prepare.js  ==  FALAH_ORIGIN في الخادم
```

إن اختلّ أيٌّ منها، تنكسر المصادقة **من أربع جهات مستقلّة**:

| # | الطبقة | ما يحدث | الدليل |
|---|---|---|---|
| ١ | CORS | لا ترويسة `Access-Control-Allow-Origin` في الخادم إطلاقًا | `grep Access-Control app.py falah/*.py → NONE` |
| ٢ | الكعكة | `api()` لا يضبط `credentials` ⇒ الافتراضي `same-origin` ⇒ **الكعكة لا تُرسل** | `grep credentials falah-app.html → NONE` |
| ٣ | SameSite | الكعكة `SameSite=Strict` ⇒ لا تُرسل عبر المواقع حتى مع `include` | `app.py:133` |
| ٤ | CSRF | `guard_csrf` يرفض إن `Origin != FALAH_ORIGIN` ⇒ **كل POST يُرفض** | `app.py:161-167` |

**و`prepare.js` يحاول إصلاح هذا بسطرين، وكلاهما لا يفعل شيئًا:**

```js
ui = ui.replace(/credentials:\s*"same-origin"/g, 'credentials: "include"');
// ← لا وجود لـ credentials في falah-app.html ⇒ استبدال بلا هدف

if (!/credentials:/.test(ui)) {
  ui = ui.replace(/const o = body \?/, 'const o = body ?');   // ← استبدال النصّ بنفسه
}
```

### ٨٫١ CSP — الفجوة الوحيدة الجوهرية

التطبيق يدرج في `innerHTML` نصوصًا شرعية وعلامة مائيّة يكتبها المستخدم.
التهريب صحيح اليوم، لكن **لا توجد طبقة ثانية**. CSP هي الطبقة التي تحوّل خطأ
تهريب مستقبليًّا من ثغرة إلى لا شيء.

ملاحظة تشدّد: `esc()` لا تهرّب `'`. الاستعمال الحالي كلّه داخل سمات مزدوجة
الاقتباس فهو **سليم**، لكنه ينكسر بصمت لو كتب أحدهم سمة بعلامة مفردة يومًا.
