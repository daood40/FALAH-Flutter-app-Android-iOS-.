# ٢ · الطابور والعامل والتصدير

مقيسٌ بتشغيلٍ حقيقيّ: خادمٌ + عاملٌ منفصل، مشروعٌ بأربع بطاقات.

| ما قيس | القيمة |
|---|---:|
| `POST /app/export` — الوضعُ في الطابور | **٤٫٧ م.ث** |
| `POST /app/video` — الوضعُ في الطابور | **٤٫٤ م.ث** |
| انتظارُ المهمّة في الطابور (`created_at → started_at`) | **٠ ث** (عاملٌ خالٍ) |
| تصييرُ أربع بطاقات (`started_at → finished_at`) | **١٢ ث** ⇒ **٣٫٠ ث/بطاقة** |
| الزمنُ الجداريّ من الطلب إلى الاكتمال | ١١٫٩ ث |
| تصييرُ مقطعٍ واحد (٤٫٤ ثانية صوت) | **٧ ث** |
| الزمنُ الجداريّ للمقطع | ٨٫١ ث |

**والفرقُ بين `enqueue` و`duration` هو ثمرةُ P0-1**: الطلبُ يعود في
أربعةِ أجزاءٍ من مئة من الثانية، والعملُ يجري خارجَه.

## حالاتُ المهمّة المرصودة اليوم

`queued · running · done · failed · canceled` — خمسٌ، مع
`attempts` و`max_attempts` و`progress` (٠–١٠٠) و`step` (نصٌّ عربيّ) و
`error` و`worker` و`not_before` و`created_at` و`started_at` و
`finished_at` و`heartbeat`.

**ولا حالةَ `retrying` منفصلة**: الإعادةُ تعيد المهمّةَ إلى `queued`
بـ`not_before` مستقبليّ و`attempts` مرفوع. أي أن «يُعاد الآن» تُشتقّ
(`state='queued' AND attempts>0`) ولا تُخزَّن.

# ٤ · حجمُ السجلّ اليوم

**قيس فعلًا** بمقارنة حجم مخرَج العملية قبل عملٍ كاملٍ وبعده:

| | |
|---|---:|
| مخرَجُ الخادم لدورةٍ كاملة (تسجيل · مشروع · ٤ عناصر · تصدير · استطلاع) | **٠ بايت** |
| مخرَجُ العامل للدورة نفسها | **٣٢ بايت · سطران** |
| مخرَجُ العامل لمقطعٍ واحد | ٣١ بايت |

**السببُ أن `log_message` مُسكَتٌ عمدًا**: لا سجلَّ وصولٍ لكل طلب. ولا
يُكتب شيءٌ إلا عند عطبٍ حقيقيّ (`log_error`) أو عند حدثِ عاملٍ.

**وهذا هو أصلُ المشكلة التي يعالجها P1.3**: النظامُ صامتٌ إلى حدِّ أنه لا
يقول شيئًا حين يعمل، فلا يُعرف بطءٌ ولا نمطُ استعمالٍ ولا موجةُ منعٍ إلا
من شكوى.

## سجلّ التدقيق — مقيس

| | |
|---|---:|
| **حجمُ الصفّ الواحد** (بحمولةٍ واقعية: وكيلُ متصفّح + بيانات) | **٣٠٢ بايت** |
| مليون حدث | **٢٨٨ م.ب** |

**وهذا رقمٌ حاسمٌ لتصميم P1.3**: كتابةٌ مهيكلةٌ في SQLite تكلّف خُمسَ
مللي ثانية. ومسارٌ زمنُه ١٫٣ م.ث لا يحتمل ثلاثَ كتاباتٍ لكل طلب.

# ٦ · معدّلاتُ الأخطاء

**`UNKNOWN`.**

لا يُعدّ النظامُ اليوم طلبًا ناجحًا ولا فاشلًا. وما يمكن استخراجُه من
`audit_logs` هو أحداثُ الأمن والوثيقة وحدها (`security.denied` ·
`login.failure`) — لا نسبةُ ٥٠٠ ولا ٤٠٠ ولا زمنُ الاستجابة.

وما قيس في هذه الجلسة **بيئةُ اختبارٍ لا إنتاج**: كلُّ الحزم تمرّ، فمعدّلُ
الخطأ صفرٌ بحكم أن الاختبار يمرّ — وهذا لا يقول شيئًا عن الإنتاج.

**ولا إنتاجَ اليوم أصلًا**: الإطلاقُ موقوفٌ حتى تُغلق `External
Verification`، فلا بياناتِ استعمالٍ حقيقيةٍ تُقاس.
